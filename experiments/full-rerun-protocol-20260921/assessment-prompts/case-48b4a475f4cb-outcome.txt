deprecated and its usage is discouraged.\"* 隐式量化仅支持 INT8，且只能与弱类型（weak typing，同样已弃用）一起使用。官方强烈建议迁移到显式量化。\n\n### 1.1 启用方式\n\n当网络中**不存在** `QuantizeLayer` / `DequantizeLayer`，且在 builder configuration 中启用 INT8 和弱类型时，TensorRT 使用隐式量化模式。隐式量化是\"机会主义\"（opportunistic）的：TensorRT 将模型视为浮点模型进行图优化，仅当某层在 INT8 下运行更快且其输入/输出已分配量化 scale 时，才为该层分配 INT8 kernel，否则回退到 FP32/FP16/BF16。\n\n每个带有 scale 的激活张量会被考虑量化，scale 来源有两种：\n- **校准（calibration）过程**自动分配；\n- 通过 **Dynamic Range API** 手动设置。\n\n### 1.2 Dynamic Range API（仅适用 INT8）\n\n由于 TensorRT 仅支持**对称量化**，scale 计算为 `max(abs(min_float), abs(max_float))`。注意：当 `abs(min_float) != abs(max_float)` 时，TensorRT 实际使用比配置更大的动态范围，可能增加舍入误差。\n\n**C++：**\n```cpp\ntensor->setDynamicRange(min_float, max_float);\n```\n\n**Python：**\n```python\ntensor.dynamic_range = (min_float, max_float)\n```\n\n参考示例：[sampleINT8API](https://github.com/NVIDIA/TensorRT/tree/main/samples/sampleINT8API)（C++）。\n\n> 手动设置 dynamic range 会**覆盖** INT8 校准生成的 dynamic range（两者可结合使用）。\n\n### 1.3 PTQ 校准流程（Builder 内部三步）\n\n1. 构建 32-bit engine，在校准集上运行，为每个张量记录激活值分布直方图（histogram）；\n2. 根据直方图生成校准表（calibration table），为每个张量提供 scale 值；\n3. 根据校准表和网络定义构建 INT8 engine。\n\n校准可能很慢，因此第 2 步的校准表可**缓存并复用**（所有校准器均支持）。\n\n### 1.4 校准数据要求\n\n| 项目 | 要求/建议 |\n|---|---|\n| **样本数量** | 与应用相关；实验表明 ImageNet 分类网络约 **500 张图像**足够 |\n| **数据格式** | 即使 builder 配置为 INT8 I/O，校准数据仍须为 **FP32**；可将 INT8 I/O 转为 FP32，且 FP32 数据须在 `[-128.0F, 127.0F]` 范围内，并能无精度损失地转回 INT8 |\n| **Batch size** | 影响 `IInt8EntropyCalibrator2` / `IInt8EntropyCalibrator` 的截断误差（truncation error）。建议**用尽可能大的单个 batch** 校准；多个小 batch size/输入不保证逐位相同 |\n\n两类误差权衡（scale 选择并非精确科学）：\n- **离散化误差（discretization error）**：每个量化值表示的范围越大，误差越大；\n- **截断误差（truncation error）**：值被钳制（clamp）到可表示范围边界。\n\n### 1.5 校准器选择建议（Entropy vs MinMax 等）\n\n| 校准器 | 实现），以保证多个量化值求和的\"平滑\"效果。\"平滑层\"指到达网络输出前的 convolution、deconvolution、fully connected 或 matrix multiplication。\n\n该启发式**不适用**的场景：\n- 网络输出类型为 INT8；\n- 从最后一个平滑层到输出路径上的某操作被 `ILayer::setOutputType` 或 `ILayer::setPrecision` 约束为输出 INT8；\n- 没有通向输出的平滑层，或路径上存在插件（plugin）层；\n- 网络使用**显式量化**。\n\n---\n\n## 2) 显式量化（Q/DQ、Model Optimizer）说明与迁移建议\n\n### 2.1 隐式 vs 显式对比（原文 Table 10）\n\n| | 隐式量化（已弃用） | 显式量化 |\n|---|---|---|\n| 支持的量化数据类型 | INT8 | **INT8, FP8, INT4, FP4** |\n| 精度控制方式 | 全局 builder flags 和 per-layer 精度 API | 直接编码在模型中（Q/DQ 节点） |\n| API | Model + Scales（dynamic range API）；Model + Calibration data | 带 Q/DQ 层的模型 |\n\n**显式量化优势**：\n- **更广的数据类型支持**：INT8、FP8、INT4、FP4；\n- **直接用户控制**：Q/DQ 节点精确控制量化/反量化发生位置；\n- **保留模型语义**：优化器只执行模型语义规定的转换，精度非常接近原框架（但由于浮点运算顺序可能改变，结果**不会逐位相同**）；\n- **与 ONNX 导出天然兼容**：框架中的 fake-quantization 操作导出为 Q+DQ 对。\n\n### 2.2 工作原理\n\n- 当网络中存在 `IQuantizeLayer`（[C++](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/_static/c-api/classnvinfer1_1_1_i_quantize_layer.html) / [Python](https://docs.nvidia.com/deeplearning/tensorrt/10.x.x/_static/python-api/infer/Graph/Layers.html#iquantizelayer)）和 `IDequantizeLayer`（C++ / Python）时，TensorRT 以显式量化逻辑构建 engine。\n- 可配合 **Strong Typing 或 Weak Typing** 使用（不需要也不应指定 precision-control build flags），但因弱类型已弃用，**建议始终使用强类型**。\n- **Q/DQ 传播（propagation）**：Q 节点向后传播（尽早量化），DQ 节点向前传播（尽量晚反量化），目标是最大化低精度处理的图比例。层 `Op` 与量化可交换（commute）的条件：`Q(Op(x)) == Op(Q(x))`；与反量化可交换：`Op(DQ(x)) == DQ(Op(x))`（原文以 Max Pooling 为例给出证明）。注意区分：**quantizable 层**（如 AveragePooling，不可交换，通过 Q/DQ 融合量化）与 **commuting 层**（如 Max Pooling）的处理方式不同。\n\n### 2.3 ONNX 支持要点\n\n- PyTorch/TensorFlow 的 QAT 模型导出 ONNX 时，每个 fake-quantization 导出为 `QuantizeLinear` + `DequantizeLinear` 对；TensorRT 导入时分别映射为 `IQuantizeLayer` / `IDequantizeLayer`。\n- **Opset 演进**：opset 10 引入 Q/DQ；opset 13 增加 quantization-axis 属性（per-channel 必需，PyTorch 1.8 起支持导出）；opset 19 增加 FP8（TensorRT 支持 E4M3FN，但 opset 19 未被完全支持）；opset 21 增加 INT4 与块量化；opset 23 增加 FP4E2M1。\n- PyTorch 2.0 不支持 FP8 格式和 opset 19 导出；`TransformerEngine` 通过 \"trt\" 域自定义算子 `TRT_FP8 QuantizeLinear` / `TRT_FP8 DequantizeLinear` 桥接（其他工具如 ONNX Runtime 无法解析这些自定义算子）。\n- ⚠️ **不支持的 ONNX 量化算子**（导入时报错）：`QLinearConv`、`QLinearMatmul`、`ConvInteger`、`MatmulInteger`。\n- GEMM 权重布局差异：PyTorch 导出 `(K, C)` + `transB`（per-channel 轴 K = 0，dimension 0）；TensorFlow 预转置 `(C, K)`（轴 K = 1，dimension 1）。TensorRT 在转置前量化权重。\n\n### 2.4 TensorRT Model Optimizer 与迁移建议\n\n**迁移建议（原文明确）**：\n> *\"Users are strongly advised to transition to explicit quantization, typically by utilizing the TensorRT Model Optimizer to create models with explicit quantization.\"*\n\n- [TensorRT Model Optimizer](https://github.com/NVIDIA/TensorRT-Model-Optimizer)：Python 工具包，用于创建 QAT 模型（完全兼容 TensorRT 优化与部署流程）；同时提供 **PTQ recipe**，支持 PyTorch 和 ONNX 格式模型的 PTQ。\n- **重要约束**：带 Q/DQ 节点的模型**不允许再提供外部校准表**（TensorRT 拒绝加载）。显式模型的校准必须在 **ONNX 导出之前**完成（如用 Model Optimizer 做 PTQ/QAT），scale 直接嵌入 Q/DQ 节点。\n- **已知差距**：某些网络上，初始显式量化的延迟可能高于隐式量化；Model Optimizer 团队正与 TensorRT 团队协作缩小该差距。\n- QAT 支持：**TensorFlow**（Model Optimizer + TF2 Keras；注意 **TF1 不支持 per-channel quantization**）；**PyTorch**（1.8.0+ 支持 per-channel scale 的 ONNX Q/DQ 导出，可用 Model Optimizer 做 INT8 校准及各精度的 QAT/PTQ 并导出 ONNX）。\n\n### 2.5 Q/DQ 放置建议（节选关键规则）\n\n1. **量化所有带权重操作（Convolution、Transposed Convolution、GEMM）的输入**（权重+激活）；\n2. **默认不量化带权重操作的输出**（保留高精度输出，例如后接 SiLU 等激活函数时）；\n3. **不要在训练框架中模拟 batch normalization 和 ReLU 融合**（TensorRT 优化保证保留其算术语义）;\n4. **量化跳跃连接（skip connection）的残差输入**（如 ResNet、EfficientNet）：element-wise add 第一个输入的精度决定融合输出精度——残差为 FP 时尾部 Q 层无法与卷积融合；残差为 INT8 时可以；\n5. 为获得额外性能，可尝试量化不与 Q/DQ 交换的层（当前非带权重层若 INT8 输入则也要求 INT8 输出，输入输出都要量化）；\n6. **保守地添加 Q/DQ 节点**，兼顾精度与性能实验——多余的 Q/DQ 会导致次优融合；\n7. **激活用 per-tensor 量化，权重用 per-channel 量化**（经验上精度最佳）；\n8. 可通过**启用 FP16** 进一步优化延迟（TensorRT 尽可能用 FP16 替代 FP32，并非所有层类型都支持）——这是所给内容中与 \"kFp16\" 最接近的表述，**未给出具体 flag 代码**。\n9. 旧设备可能缺少部分层的低精度 kernel 实现，构建时报 `could not find any implementation` 错误 → 解决方法是移除量化该失败层的 Q/DQ 节点。\n\n### 2.6 其他显式量化要点\n\n- **量化权重**：Q/DQ 模型权重可用高精度（FP32/FP16/BF16）或低精度（INT8/FP8/INT4/FP4）指定；高精度权重在 build 时按 `IQuantizeLayer` 的 scale 量化后存入 engine plan；预量化权重与线性算子之间必须有 `IDequantizeLayer`。INT4/FP4 权重按**每字节 2 个元素**打包（第 1 个元素存低 4 位，第 2 个存高 4 位）。\n- **Weight-Only Quantization（WoQ）**：仅适用于 **INT4 块量化 + GEMM 层**；GEMM 输入与计算保持高精度（FP32/FP16/BF16），权重 4-bit 存储、计算前反量化，适用于内存带宽受限或显存紧张场景。\n- **Q/DQ 限制**：某些图重写依赖多个 Q/DQ 层 scale 相等；refittable engine 重新 fit 时若新 scale 破坏这些优化前提，会**抛出异常**。\n- **插件交互**：插件消费/产生 INT8/FP8 时，须将输入 DQ、输出 Q 节点纳入插件内部（\"手动融合\" `DQ_i`/`Q_o`，把 scale 传给插件），并对插件层调用 `setOutputType(kINT8)`。\n\n---\n\n## 3) 硬件要求（Compute Capability）—— ⚠️ 所给内容中缺失\n\n**所提供的网页内容不包含任何 compute capability（如 sm_XX）的具体数值要求。** 正文中与硬件相关的信息仅有：\n\n- 舍入模式表区分了 **GPU** 与 448]`）：`xq = castToFp8(clip(x/s, -448, 448))`，ties-to-even。\n\n**INT4**（范围 `[-8, 7]`，块大小 `{64, 128}`，仅权重量化 WoQ）：`xq = roundWithTiesToEven(clip(x/s, -8, 7))`。\n\n**NVFP4**（FP4E2M1，范围 `[-6, 6]`，块大小 16，激活须用动态量化）：`xq = castToFp4(clip(x/s, -6, 6))`。\n\n**动态量化 scale**：`scale = max_i(abs(x_i)) / qTypeMax`；**MXFP8**（OCP MX 规范，块 32，E8M0 scale）：`scale_E8M0 =
