\"tensorrt_plan\"\n  max_batch_size: 8\n  input [\n    {\n      name: \"input0\"\n      data_type: TYPE_FP32\n      dims: [ 16 ]\n    },\n    {\n      name: \"input1\"\n      data_type: TYPE_FP32\n      dims: [ 16 ]\n    }\n  ]\n  output [\n    {\n      name: \"output0\"\n      data_type: TYPE_FP32\n      dims: [ 16 ]\n    }\n  ]\n```\n\n其他使用 `tensorrt_plan` 的示例见下文各章节（shape tensors、non-linear I/O、version_policy 等）。\n\n---\n\n## 2. max_batch_size\n\n**来源章节：Maximum Batch Size**\n\n- `max_batch_size` 指示模型支持的、可被 Triton 利用的各种批处理类型的最大批大小。\n- 若模型的 batch 维度是第一个维度，且模型的所有输入输出都含此 batch 维度，则 Triton 可使用 **dynamic batcher** 或 **sequence batcher** 自动对该模型进行批处理。此时 `max_batch_size` 应设为 **≥ 1** 的值，表示 Triton 对该模型使用的最大批大小。\n- 对于不支持批处理、或不支持上述特定批处理方式的模型，`max_batch_size` **必须设为 0**。\n\n**批处理开启时（max_batch_size > 0）需配合 dynamic_batching：**\n\n```\n  platform: \"tensorrt_plan\"\n  max_batch_size: 8\n  input [\n    {\n      name: \"input0\"\n      data_type: TYPE_FP32\n      dims: [ 16 ]\n    }\n  ]\n  output [\n    {\n      name: \"output0\"\n      data_type: TYPE_FP32\n      dims: [ 4 ]\n    }\n  ]\n```\n\n此时 input0 完整形状为 `[-1, 16]`，output0 为 `[-1, 4]`。\n\n**max_batch_size = 0 时：**\n\n```\n  platform: \"tensorrt_plan\"\n  max_batch_size: 0\n  input [\n    {\n      name: \"input0\"\n      data_type: TYPE_FP32\n      dims: [ 16 ]\n    }\n  ]\n  output [\n    {\n      name: \"output0\"\n      data_type: TYPE_FP32\n      dims: [ 4 ]\n    }\n  ]\n```\n\n此时 input0 形状为 `[16]`，output0 为 `[4]`。\n\n---\n\n## 3. input / output 段完整语法\n\n**来源章节：Inputs and Outputs**\n\n每个模型输入和输出必须指定 **name、datatype 和 shape**。输入/输出 tensor 的 name 必须与模型期望的名称匹配。\n\n### 3.1 形状规则\n\n- 输入/输出形状 rank 必须 ≥ 1，即**不允许空形状 `[ ]`**。\n- 完整形状由 `max_batch_size` 与 `dims` 组合而成：\n  - `max_batch_size > 0`：完整形状 = `[-1] + dims`\n  - `max_batch_size = 0`：完整形状 = `dims`\n- 支持可变维度时用 `-1` 表示。例如要求第一维为 4、第二维任意，可写 `dims: [ 4, -1 ]`。配置可比底层模型更严格，如写 `dims: [ 4, 4 ]` 则 Triton 只接受形状恰为 `[4, 4]` 的请求。\n- 若推理请求收到的输入形状与模型期望形状不匹配（或输出形状不匹配），必须使用 **`reshape`** 属性。\n- 输入可指定 `allow_ragged_batch` 表明该输入是 ragged input，与 dynamic batcher 配合使用，允许批处理时不强制所有请求中该输入形状一致。\n\n### 3.2 PyTorch 后端特殊命名约定\n\n1. **[仅输入]** 当输入不是 Tensor 字典时，配置中的输入名应与模型定义中 forward 函数的参数名一致。例如 forward 定义为 `forward(self, input0, input1)`，则两个输入分别命名为 \"input0\" 和 \"input1\"。\n2. **`<name>__<index>`**：`<name>` 可为任意字符串，`<index>` 为对应输入/输出位置的整数索引。例如两个输入两个输出可命名为 \"INPUT__0\"、\"INPUT__1\" 和 \"OUTPUT__0\"、\"OUTPUT__1\"。\n3. 若所有输入（或输出）未遵循同一命名约定，则强制按配置中的顺序，即假定配置中输入（或输出）的顺序即真实顺序。\n\n**Tensor 字典作为输入（仅 PyTorch）：** 仅当模型有*单一*输入且为字符串到 tensor 的映射字典时支持。例如模型期望输入：\n\n```\n{'A': tensor1, 'B': tensor2}\n```\n\n此时输入名**不得**使用 `<name>__<index>` 约定，而必须映射到各 tensor 的字符串 'key'，即输入名为 \"A\"（对应 tensor1）和 \"B\"（对应 tensor2）。\n\n### 3.3 reshape 示例\n\n输入（batch 维完全描述形状时）：\n\n```\n  input [\n    {\n      name: \"in\"\n      dims: [ 1 ]\n      reshape: { shape: [ ] }\n    }\n  ]\n```\n\n输出：\n\n```\n  output [\n    {\n      name: \"in\"\n      dims: [ 1 ]\n      reshape: { shape: [ ] }\n    }\n  ]\n```\n\n### 3.4 数据类型对照表（与 TensorRT 相关重点）\n\n| Model Config | TensorRT | ONNX Runtime | PyTorch | API | NumPy |\n|---|---|---|---|---|---|\n| dynamic_batching（Default Max Batch Size and Dynamic Batcher）\n\n**来源章节：Default Max Batch Size and Dynamic Batcher**\n\n- 使用 auto-complete 特性时，可通过 `--backend-config=default-max-batch-size=<int>` 命令行参数设置默认最大批大小。默认值为 **4**。\n- 后端开发者可通过 `TRITONBACKEND_BackendConfig` API 获取该值。目前利用该默认值并在生成配置中开启 dynamic batching 的后端有：\n  1. **Onnxruntime backend**\n  2. **TensorRT backend** —— TensorRT 模型显式存储最大批大小，不使用 default-max-batch-size 参数。但若 `max_batch_size > 1` 且未提供调度器，将启用 dynamic batch scheduler。\n- 若为模型设置了大于 1 的 max_batch_size，且配置文件中未提供调度器，则会设置 `dynamic_batching` 配置。\n\n---\n\n## 5. instance_group（Instance Groups 完整章节）\n\nTriton 可提供模型的多个实例，使多个推理请求可被同时处理。`ModelInstanceGroup` 属性用于指定执行实例数量及所用的计算资源。\n\n### 5.1 多模型实例\n\n默认为系统每个可用 GPU 创建一个执行实例。可在每个 GPU 或指定 GPU 上放置多个实例。\n\n每个 GPU 上 2 个实例：\n\n```\n  instance_group [\n    {\n      count: 2\n      kind: KIND_GPU\n    }\n  ]\n```\n\nGPU 0 上 1 个实例，GPU 1 和 2 上各 2 个实例：\n\n```\n  instance_group [\n    {\n      count: 1\n      kind: KIND_GPU\n      gpus: [ 0 ]\n    },\n    {\n      count: 2\n      kind: KIND_GPU\n      gpus: [ 1, 2 ]\n    }\n  ]\n```\n\n### 5.2 CPU 模型实例\n\n即使系统中有 GPU，也可在 CPU 上执行模型。在 CPU 上放置 2 个实例：\n\n```\n  instance_group [\n    {\n      count: 2\n      kind: KIND_CPU\n    }\n  ]\n```\n\n若 KIND_CPU 实例组未指定 `count`，则部分后端默认实例数为 2，其余后端默认为 1。\n\n### 5.3 Host Policy\n\n实例组设置可关联 host policy，将实例组创建的所有实例与 host policy 关联。默认按实例的设备类型设置：KIND_CPU 为 \"cpu\"，KIND_MODEL 为 \"model\"，KIND_GPU 为 \"gpu_<gpu_id>\"：\n\n```\n  instance_group [\n    {\n      count: 2\n      kind: KIND_CPU\n      host_policy: \"policy_0\"\n    }\n  ]\n```\n\n### 5.4 Rate Limiter 配置\n\n实例组可选择性地指定 rate limiter 配置。关闭 rate limiting 时忽略此配置；开启时若实例组未提供配置，则该组实例不受限。包含：\n\n- **Resources**：执行模型实例所需资源集合。\"name\" 标识资源，\"count\" 指所需副本数，\"global\" 指定资源是 per-device 还是全系统共享。同一资源不能同时声明为 global 和非 global。若无资源，Triton 假定实例无需资源、实例可用即开始执行。\n- **Priority**：作为所有模型所有实例间优先调度的权重值。priority 为 2 的实例获得的调度机会是 priority 为 1 的实例的 1/2。\n\n示例（设备 0/1/2 各建 1 实例，各需 4 个 [4,1,3]\ninput1: [4, 4, 6] <== shape of this tensor [3]\n\n```\n\n### 7.2 Non-Linear I/O Formats（仅 TensorRT 支持）\n\n对以非线性格式处理输入/输出数据的模型，必须设置 `is_non_linear_format_io` 属性。示例指定 INPUT0 和 INPUT1 使用非线性 I/O
