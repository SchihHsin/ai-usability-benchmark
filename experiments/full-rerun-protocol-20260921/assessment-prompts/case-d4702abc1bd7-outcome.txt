收集AI Core Error问题信息\n\n#### 收集信息类别介绍\n\n**注意**：在收集日志时，需收集本次AI Core Error问题附近时间的日志，旧日志中的不相关信息或其它报错信息可能导致后续msaicerr工具分析AI Core Error问题时报错。\n\n信息类别\n\n用途说明\n\n应用类日志\n\n在Host或Device上运行应用程序产生的调试或运行日志，用于查看用户态日志。\n\ntrace日志\n\n查看软件栈的维测信息。\n\n算子exception Core Error信息时，涉及各类日志的获取、环境变量的设置，日志获取路径以默认路径来说明、环境变量设置方法以示例来说明：\n\n- 关于日志级别、日志路径以及日志文件的详细介绍请参见《[日志参考](https://www.hiascend.com/document/detail/zh/canncommercial/850/maintenref/logreference/logreference_0001.html)》。\n- 关于环境变量的详细说明及约束，请参见《[环境变量参考](https://www.hiascend.com/document/detail/zh/canncommercial/850/maintenref/envvar/envref_07_0001.html)》。\n\n#### 收集信息前先判断是否需要复跑业务\n\n**注意**：如果日志中的时间与发生AI Core Error问题的时间相距较远，则旧日志可能已经被覆盖或清理，这种场景需复跑业务后，再收集故障信息。\n\n场景\n\n是否复跑\n\n依赖PyTorch/MindSpore/TensorFlow框架的业务，例如**训练、在线推理**等\n\n**无需复跑业务**\n\n系统默认记录定位AI Core Error问题的信息。\n\n不依赖或不使用PyTorch/MindSpore/TensorFlow框架的业务，例如**离线推理、单算子调用、构图**等。\n\n**需复跑业务**\n\n用户手动收集部分信息时，需要先设置环境变量、再跑业务，才能收集。例如收集算子exception dump文件时，需要先设置NPU_COLLECT_PATH环境变量。关于NPU_COLLECT_PATH的详细描述请参见《[环境变量参考](https://www.hiascend.com/document/detail/zh/canncommercial/850/maintenref/envvar/envref_07_0001.html)》中的“故障信息收集 > [NPU_COLLECT_PATH](https://www.hiascend.com/document/detail/zh/canncommercial/850/maintenref/envvar/envref_07_0130.html)”。关于手动收集信息的详细描述请参见[用户手动收集步骤](https://www.hiascend.com/document/detail/zh/canncommercial/850/maintenref/troubleshooting/troubleshooting_0006.html#ZH-CN_TOPIC_0000002502730206__section420651516422)。\n\n若设置了环境变量NPU_COLLECT_PATH，会导致业务变慢，影响性能，不建议长期开启，定位问题之后建议及时关闭。\n\n说明：\n\n性能敏感、但磁盘资源充足的情况下，后续希望在不复跑业务的情况下自动生成exception dump文件分析AI Core Error问题，可调用aclInit接口开启异常算子Dump配置（即在json文件中配置dump_scene参数）。该方式下，大部分网络，性能影响在1%以下，但开启后，多次AI Core Error问题生成的dump文件会消耗磁盘空间，用户需自行清理历史dump数据。详细接口说明请参见“[aclInit](https://www.hiascend.com/document/detail/zh/canncommercial/850/API/appdevgapi/aclcppdevg_03_0022.html)”章节。\n\n#### 收集信息方式介绍\n\n定位AI Core
