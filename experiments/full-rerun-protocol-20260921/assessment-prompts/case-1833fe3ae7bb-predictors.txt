      // 框架适配层\n    │   ├── CMakeLists.txt\n    │   └── tf_plugin               // TensorFlow 插件\n    │       ├── CMakeLists.txt\n    │       └── tensorflow_add_custom_plugin.cc\n    ├── op_host 深度解析\n\n[add_custom.json](https://link.gitcode.com/i/0164e4a7e9acc2910c8d280c0fb48eac) 是 msopgen 的输入核心，它以 JSON 数组描述一个或多个算子的原型。本样例仅定义一个 `AddCustom` 算子：\n\n```\n[\n    {\n        \"op\": \"AddCustom\",\n        \"language\": \"cpp\",\n        \"input_desc\": [\n            {\n                \"name\": \"x\",\n                \"param_type\": \"required\",\n                \"format\": [\"ND\"],\n                \"type\": [\"fp16\"]\n            },\n            {\n                \"name\": \"y\",\n                \"param_type\": \"required\",\n                \"format\": [\"ND\"],\n                \"type\": [\"fp16\"]\n            }\n        ],\n        \"output_desc\": [\n            {\n                \"name\": \"z\",\n                \"param_type\": \"required\",\n                \"format\": [\"ND\"],\n                \"type\": [\"fp16\"]\n            }\n        ],\n        \"attr\": []\n    }\n]\n```\n\n字段含义与取值说明：\n\n字段 本样例取值 含义说明 `op` `AddCustom` 算子名称，将作为算子定义、ACLNN 接口命名（如 `aclnnAddCustom`）以及插件注册名的基础 `language` `cpp` 算子实现语言，与 `msopgen gen` 命令中的 `-lan cpp` 对应 `input_desc` / `output_desc` `x`、`y`（输入），`z`（输出） 输入/输出描述数组，每个元素含 `name`（张量名）、`param_type`（参数类型）、`format`（数据排布格式）、`type`（数据类型） `param_type` `required` 必选参数，表示该输入/输出在调用时不可省略 `format` `[\"ND\"]` 数据排布格式为 ND（普通多维数组排布） `type` `[\"fp16\"]` 数据类型为半精度浮点 fp16，与 Kernel 侧 `DTYPE_X/DTYPE_Y/DTYPE_Z` 的宏定义及 Host 侧注册的 `ge::DT_FLOAT16` 一致 `attr` `[]` 算子属性列表，本样例无属性\n\n**从源码印证**：将 JSON 中的 `input_desc`/`output_desc` 与 [Host 侧算子定义注册](https://link.gitcode.com/i/d147e53c88b88b339d4bdfe662024c45) 对照即可发现，二者描述完全一致——`this->Input(\"x\").ParamType(REQUIRED).DataType({ge::DT_FLOAT16}).Format({ge::FORMAT_ND})` 等注册语句就是 JSON 描述在代码层面的落点。因此，修改原型定义（如增删输入、调整 dtype）后，Host 侧注册代码也需要同步修改，二者必须保持一致。\n\n## 五、Host 侧与 Kernel 侧算子实现源码剖析\n\n### 5.1 Tiling 数据结构定义\n\n[add_custom_tiling.h](https://link.gitcode.com/i/203cc252050d8a87f79e85e1a7b6164b) 定义了 Host 与 Kernel 之间传递的 Tiling（切分）信息结构：\n\n```\nstruct AddCustomTilingData {\n    uint32_t totalLength;   // 输入张量总元素个数\n    uint32_t tileNum;       // 每个 block 内循环切分的份数\n};\n```\n\n该结构体同时被 Host 侧（Tiling 函数填充）和 Kernel 侧（核函数读取）引用，是 Host/Kernel 通信的桥梁。\n\n### 5.2 Host 侧：Tiling 计算与算子注册\n\n[Host 侧实现](https://link.gitcode.com/i/ccd08515fd221e85f2faa79f4ff32bc7) 包含两个关键部分：\n\n**（1）Tiling 函数（`optiling::TilingFunc`）**：\n\n```\nconst uint32_t BLOCK_DIM = 8;   // 使用的 AI Core 数量（block 维度）\nconst uint32_t TILE_NUM = 8;    // 每个 block 内循环切分份数\n\nstatic ge::graphStatus TilingFunc(gert::TilingContext* context)\n{\n    AddCustomTilingData* tiling = context->GetTilingData<AddCustomTilingData>();\n    uint32_t totalLength = context->GetInputShape(0)->GetOriginShape().GetShapeSize();\n    context->SetBlockDim(BLOCK_DIM);\n    tiling->totalLength = totalLength;\n    tiling->tileNum = TILE_NUM;\n    return ge::GRAPH_SUCCESS;\n}\n```\n\n其核心逻辑是：从 `TilingContext` 中取出输入 0 的原始 shape，计算总元素数 `totalLength`，设置并行 block 数 `BLOCK_DIM = 8`，并将 `totalLength`、`tileNum` 写入 Tiling 数据结构供 Kernel 使用。**这是算子在多核上并行切分的决策点**——`BLOCK_DIM` 决定启用多少 AI Core，`tileNum` 决定单核内数据搬入-计算-搬出的流水循环次数。\n\n**（2）算子定义注册（`ops::AddCustom` 类）**：\n\n```\nclass AddCustom : public OpDef {\npublic:\n    explicit AddCustom(const char* name) : OpDef(name)\n    {\n        this->Input(\"x\").ParamType(REQUIRED).DataType({ge::DT_FLOAT16}).Format({ge::FORMAT_ND});\n        this->Input(\"y\").ParamType(REQUIRED).DataType({ge::DT_FLOAT16}).Format({ge::FORMAT_ND});\n        this->Output(\"z\").ParamType(REQUIRED).DataType({ge::DT_FLOAT16}).Format({ge::FORMAT_ND});\n        this->AICore()\n            .SetTiling(optiling::TilingFunc)\n            .AddConfig(\"ascend910\")\n            .AddConfig(\"ascend310p\")\n            .AddConfig(\"ascend310b\")\n            .AddConfig(\"ascend910b\")\n            .AddConfig(\"ascend950\");\n    }\n};\nOP_ADD(AddCustom);\n```\n\n这里通过 `OP_ADD(AddCustom)` 完成算子向图引擎的注册，并通过 `AddConfig(...)` 声明算子适配的多个昇腾芯片型号（ascend910/310p/310b/910b/950）。**注意**：配置文件里 `AddConfig` 支持的芯片型号列表决定了算子包可安装的目标设备范围，实际安装运行请以你的 NPU 型号在列表中存在为前提。\n\n### 5.3 Kernel 侧：核函数实现\n\n[Kernel 侧实现](https://link.gitcode.com/i/ea6943d7b6de8ed9f7b5811d75c8a57f) 采用 Ascend C 标准的\"多缓冲 + 流水\"编程模型：\n\n- **`KernelAdd` 类**：封装了 `Init`、`Process`、`CopyIn`、`Compute`、`CopyOut` 五个方法；\n- **Init**：按 `blockLength = totalLength / GetBlockNum()` 计算每个 block 负责的数据量，通过 `xGm.SetGlobalBuffer(...)` 按 `GetBlockIdx()` 偏移设置各自的全局内存视图，并用 `pipe.InitBuffer` 为三个队列（两个输入队列、一个输出队列）各分配 `BUFFER_NUM = 2` 个缓冲；\n- **Process**：以 `loopCount = tileNum * BUFFER_NUM` 为循环次数，依次执行 `CopyIn → Compute → CopyOut`，借助双缓冲实现数据搬入（`DataCopy`）、向量计算（`AscendC::Add`）与结果搬出（`DataCopy`）的重叠流水；\n- **入口函数**：\n\n```\nextern \"C\" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z,\n                                                 GM_ADDR workspace, GM_ADDR tiling)\n{\n    REGISTER_TILING_DEFAULT(AddCustomTilingData);\n    GET_TILING_DATA(tilingData, tiling);\n    KernelAdd op;\n    op.Init(x, y, z, tilingData.totalLength, tilingData.tileNum);\n    op.Process();\n}\n```\n\n入口通过 `REGISTER_TILING_DEFAULT` / `GET_TILING_DATA` 将 Host 侧填写的 Tiling 数据取出，再完成算子初始化与执行。**Host 侧 `TilingFunc` 写入的 `totalLength`、`tileNum` 正是在这里被读取并使用**，两条链路在数据层面闭环。\n\n## 六、ACLNN 调用验证程序解析\n\n`aclnn_invocation` 目录提供了一份完整的、可独立编译运行的 ACLNN API 调用示例（与 asc-devkit 仓库中的同款示例一致），用于验证前面生成的 AddCustom 算子。核心调用流程体现在 [main.cpp](https://link.gitcode.com/i/5dd3626ab082d2e94b68bc646fe7847d) 中，分为五个阶段：\n\n1. **运行时初始化**：`aclnnInit(nullptr)`、`aclrtSetDevice(0)`、`aclrtCreateStream(&stream)` 完成 ACL 运行时、设备与流的初始化；\n2. **张量创建与数据准备**：以 shape `{8, 2048}`（共 16384 个 fp16 元素）创建三个 `aclTensor`（输入 `input0`、`input1`、输出 `output0`），`aclrtMalloc` 分配设备内存，`aclrtMemcpy` 将 Host 数据拷入设备——输入全为 1.0 和 2.0，期望输出为 3.0（`goldenData`）；\n3. **获取 workspace 并执行**：`aclnnAddCustomGetWorkspaceSize(input0, input1, output0, &workspaceSize, &executor)` 查询所需 workspace 大小与执行器，随后 `aclnnAddCustom(workspaceDeviceMem, workspaceSize, executor, stream)` 在流上异步执行算子；\n4. **同步与取回结果**：`aclrtSynchronizeStream(stream)` 等待执行完成，`aclrtMemcpy` 将设备输出拷回 Host，并打印前 10 个元素；\n5. **校验与清理**：用 `std::equal` 将输出与 golden（全 3.0）逐元素比对，打印 `test pass` 或 `test failed`，最后依次销毁张量、释放内存、销毁流、`aclrtResetDevice`、`aclnnFinalize`。\n\n与之配套的 [CMakeLists.txt](https://link.gitcode.com/i/1fc3c81fa49c0b0f24c2c01855b08c36) 揭示了调用程序与自定义算子包的链接方式：\n\n-
