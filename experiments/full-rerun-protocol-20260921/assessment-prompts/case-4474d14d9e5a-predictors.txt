CUDA Streams\n\n> \"At the most basic level, a CUDA stream is an abstraction which allows the programmer to express a sequence of operations. A stream operates like a work-queue into which programs can add operations, such as memory copies or kernel launches, to be executed in order.\"\n\nOperations in a given stream execute sequentially, in enqueue order. Multiple streams may run simultaneously; the runtime picks tasks based on GPU resource state. Streams may have priorities (hints only, no guaranteed order).\n\nAPI calls and kernel launches in a stream are asynchronous with respect to the host thread. Creating and Destroying CUDA Streams\n\nCreated with `cudaStreamCreate()`; it initializes the stream handle.\n```c\ncudaStream_t stream;                  // Stream handle\ncudaStreamCreate(&stream);            // Create a new stream\n\n// stream based operations ...\n\ncudaStreamDestroy(stream);            // Destroy the stream\n```\n> \"If the device is still doing work in stream `stream` when the application calls `cudaStreamDestroy()`, the stream will complete all the work in the stream before being destroyed.\"\n\n### 2.5.2.2. Launching Kernels in CUDA Streams\n\nThe triple-chevron syntax accepts the stream as an extra parameter:\n```c\nkernel<<<grid, block, shared_mem_size, stream>>>(...);\n```\nThe launch is asynchronous and returns immediately.\n\n### 2.5.2.3. Launching Memory Transfers in CUDA Streams\n\nUse **`cudaMemcpyAsync()`** (like `cudaMemcpy()` but with a stream parameter):\n```c\n// Copy `size` bytes from `src` to `dst` in stream `stream`\ncudaMemcpyAsync(dst, src, size, cudaMemcpyHostToDevice, stream);\n```\nUnlike `cudaMemcpy()`, which blocks until complete, this returns immediately. Other transfers such as `cudaMemcpy2D()` also have asynchronous variants.\n\n> **Note (constraint):** \"In order for memory copies involving CPU memory to be carried out asynchronously, the host buffers must be pinned and page-locked. `cudaMemcpyAsync()` will function correctly if host memory which is not pinned and page-locked is used, but it will revert to a synchronous behavior which will not overlap with other work. This can inhibit the performance benefits of using asynchronous memory transfers. It is recommended programs use `cudaMallocHost()` to allocate buffers which will be used to send or receive data from GPUs.\"\n\n**Pinned / page-locked memory key points:**\n- Required for truly asynchronous host↔device copies → enables overlap with other work.\n- Non-pinned memory → `cudaMemcpyAsync()` silently reverts to synchronous behavior (no overlap; performance benefit lost).\n- Recommended allocation API: **`cudaMallocHost()`**.\n\n### 2.5.2.4. Stream Synchronization\n\nTwo methods to wait for a stream to be empty:\n\n**Blocking — `cudaStreamSynchronize()`:**\n```c\n// Wait for the stream to be empty of tasks\ncudaStreamSynchronize(stream);\n\n// At this point the stream is done\n// and we can access the results of stream operations safely\n```\n\n**Non-blocking — `cudaStreamQuery()`:** returns `cudaSuccess` if stream is empty; `cudaErrorNotReady` if not empty.\n```c\ncudaError_t status = cudaStreamQuery(stream);\n\nswitch (status) {\ncase cudaSuccess:\n    std::cout << \"The stream is empty\" << std::endl;\n    break;\ncase cudaErrorNotReady:\n    std::cout << \"The stream is not empty\" << std::endl;\n    break;\ndefault:\n    // An error occurred - we should handle this\n    break;\n};\n```\n\n---\n\n## 2.5.3. CUDA Events\n\n> \"CUDA events are a mechanism for inserting markers into a CUDA stream. They are essentially like tracer particles that can be used to track the progress of tasks in a stream.\"\n\nBenefit: allows a dependent operation to start after a specific kernel completes (not waiting for the whole stream). Enqueuing an event between two kernels lets a CPU thread or another stream wait on that event. This builds a dependency graph → leads into CUDA Graphs. Events also record timing information.\n\n### 2.5.3.1. Creating and Destroying CUDA Events\n```c\ncudaEvent_t event;\n\n// Create the event\ncudaEventCreate(&event);\n\n// do some work involving the event\n\n// Once the work is done and the event is no longer needed\n// we can destroy the event\ncudaEventDestroy(event);\n```\n> \"The application is responsible for destroying events when they are no longer needed.\"\n\n### 2.5.3.2. Inserting Events into CUDA Streams\nVia `cudaEventRecord()`:\n```c\ncudaEvent_t event;\ncudaStream_t stream;\n\ncudaEventCreate(&event);\ncudaEventRecord(event, stream);\n```\n\n### 2.5.3.3. Timing Operations in CUDA Streams\n\nAn event records a timestamp when it reaches the front of the stream. Surround a kernel with two events for timing:\n```c\ncudaStream_t stream;\ncudaStreamCreate(&stream);\n\ncudaEvent_t start;\ncudaEvent_t stop;\ncudaEventCreate(&start);\ncudaEventCreate(&stop);\n\ncudaEventRecord(start, stream);          // record the start event\n\nkernel<<<grid, block, 0, stream>>>(...); // launch the kernel\n\ncudaEventRecord(stop, stream);           // record the stop event\n\ncudaStreamSynchronize(stream);           // both events will have been triggered\n\nfloat elapsedTime;\ncudaEventElapsedTime(&elapsedTime, start, stop);\nstd::cout << \"Kernel execution time: \" << elapsedTime << \" ms\" << std::endl;\n\ncudaEventDestroy(start);\ncudaEventDestroy(stop);\ncudaStreamDestroy(stream);\n```\n\n### 2.5.3.4. Checking the Status of CUDA Events\n\n**Blocking — `cudaEventSynchronize()`:** blocks until the event completes. Example: kernel → event → kernel2; waiting on the event guarantees kernel1 completed, so a dependent CPU task can launch potentially before kernel2 finishes.\n```c\ncudaEvent_t event;\ncudaStream_t stream;\n\ncudaStreamCreate(&stream);\ncudaEventCreate(&event);\n\nkernel<<<grid, block, 0, stream>>>(...);   // launch a kernel into the stream\ncudaEventRecord(event, stream);            // Record the event\nkernel2<<<grid, block, 0, stream>>>(...);  // launch a kernel into the stream\n\n// Wait for the event to complete\n// Kernel 1 will be guaranteed to have completed\n// and we can launch the dependent task.\ncudaEventSynchronize(event);\ndependentCPUTask();\n\n// Wait for the stream to be empty\n// Kernel 2 is guaranteed to have completed\ncudaStreamSynchronize(stream);\n\ncudaEventDestroy(event);\ncudaStreamDestroy(stream);\n```\n\n**Non-blocking — `cudaEventQuery()`:** allows overlapping CPU work with GPU kernel execution and a device→host copy. Example enqueues kernel1 → event → kernel2 in `stream1`; while kernels run, the CPU checks whether the event completed yet and, if so, launches a non-blocking D2H copy into `stream2`:\n```c\ncudaEvent_t event;\ncudaStream_t stream1;\ncudaStream_t stream2;\n\nsize_t size = LARGE_NUMBER;\nfloat *d_data;\nfloat *h_data;\n\ncudaMalloc(&d_data, size);\ncudaMallocHost(&h_data, size);       // pinned host buffer\n\ncudaStreamCreate(&stream1);          // Processing stream\ncudaStreamCreate(&stream2);          // Copying stream\nbool copyStarted = false;\n\ncudaEventCreate(&event);\n\nkernel1<<<grid, block, 0, stream1>>>(d_data, size);\ncudaEventRecord(event, stream1);     // event after kernel1\n\nkernel2<<<grid, block, 0, stream1>>>();\n\nwhile (not allCPUWorkDone() || not copyStarted) {\n    doNextChunkOfCPUWork();\n\n    if (not copyStarted) {\n        if (cudaEventQuery(event) == cudaSuccess) {\n            cudaMemcpyAsync(h_data, d_data, size, cudaMemcpyDeviceToHost, stream2);\n            copyStarted = true;\n        }\n    }\n}\n\ncudaStreamSynchronize(stream1);\ncudaStreamSynchronize(stream2);\n\ncudaEventDestroy(event);\ncudaStreamDestroy(stream1);\ncudaStreamDestroy(stream2);\ncudaFree(d_data);\nfree(h_data);\n```\n\n---\n\n## 2.5.4. Callback Functions from Streams\n\nTwo functions exist for launching host functions from within a stream: **`cudaLaunchHostFunc()`** and **`cudaAddCallback()`**. Note: `cudaAddCallback()` is **slated for deprecation** — applications should use `cudaLaunchHostFunc()`.\n\n**`cudaLaunchHostFunc()`** signature:\n```c\ncudaError_t cudaLaunchHostFunc(cudaStream_t stream, void (*func)(void*), void *data);\n```\nParameters:\n- `stream` — the stream to launch the callback into\n- `func` — the callback function to launch\n- `data` — pointer to data passed to the callback\n\nHost function signature:\n```c\nvoid hostFunction(void *data);\n```\n\n**Caveat/constraint:** \"the host function may not call any CUDA APIs.\"\n\nExecution guarantees provided (for use with unified memory):\n- The stream is considered idle for the duration of the function's execution (the function may always use memory attached to its stream).\n- The start of the function's execution has the same effect as synchronizing an event recorded in the same stream immediately prior — it synchronizes streams \"joined\" prior to the function.\n- Adding device work to any stream does not make the stream active until all preceding host functions and stream callbacks have executed.\n- Completion of the function does not cause a stream to become active (except as described); the stream remains idle if no device work follows, and across consecutive host functions/callbacks without device work in between — so stream synchronization can be done by signaling from a host function at the end of the stream.\n\n### 2.5.4.1. Using `cudaStreamAddCallback()`\n\n> **Note:** \"The `cudaStreamAddCallback()` function is slated for deprecation and removal and is discussed here for completeness and because it may still appear in existing code. Applications should use or switch to using `cudaLaunchHostFunc()`.\"\n\nSignature:\n```c\ncudaError_t cudaStreamAddCallback(cudaStream_t stream,\n                                  cudaStreamCallback_t callback,\n                                  void *userData,\n                                  unsigned int flags);\n```\nParameters:\n- `stream` — stream to launch the callback into\n- `callback` — the callback function to launch\n- `userData` — pointer to data passed to the callback\n- `flags` — \"Currently, this parameter must be 0 for future compatibility.\"\n\nCallback function signature:\n```c\nvoid callbackFunction(cudaStream_t stream, cudaError_t status, void *userData);\n```\nParameters:\n- `stream` — stream handle from which the callback was launched\n- `status` — status of the stream operation that triggered the callback (contains current error status of the stream, possibly set by previous operations)\n- `userData` — pointer to data passed to the callback\n\nSame constraints as `cudaLaunchHostFunc()`: the stream will not advance to tasks until the host function completes, and **no CUDA functions may be called from within the callback**.\n\n### 2.5.4.2. Asynchronous Error Handling\n\n> \"errors may originate from any operation in the stream, including for kernel launches and memory transfers. These errors may not be propagated back to the user at run-time until the stream is synchronized, for example, by waiting for an event or calling `cudaStreamSynchronize()`.\"\n\nTwo ways to find errors:\n- **`cudaGetLastError()`** — returns and **clears** the last error in any stream in the current context. A second immediate call would return `cudaSuccess` if no other error occurred in between.\n- **`cudaPeekAtLastError()`** — returns the last error in the current context **but does not clear it**.\n\nBoth return `cudaError_t`. Printable names via `cudaGetErrorName()` and `cudaGetErrorString()`.\n\n**Listing 1 — Example of using cudaGetLastError() and cudaPeekAtLastError():**\n```c\n// Some work occurs in streams.\ncudaStreamSynchronize(stream);\n\n// Look at the last error but do not clear it\ncudaError_t err = cudaPeekAtLastError();\nif (err != cudaSuccess) {\n    printf(\"Error with name: %s\\n\", cudaGetErrorName(err));\n    printf(\"Error description: %s\\n\", cudaGetErrorString(err));\n}\n\n// Look at the last error and clear it\ncudaError_t err2 = cudaGetLastError();\nif (err2 != cudaSuccess) {\n    printf(\"Error with name: %s\\n\", cudaGetErrorName(err2));\n    printf(\"Error description: %s\\n\", cudaGetErrorString(err2));\n}\n\nif (err2 != err) {\n    printf(\"As expected, cudaPeekAtLastError() did not clear the error\\n\");\n}\n\n// Check again\ncudaError_t err3 = cudaGetLastError();\nif (err3 == cudaSuccess) {\n    printf(\"As expected, cudaGetLastError() cleared the error\\n\");\n}\n```\n\n**Tip (debugging constraint):** Set environment variable **`CUDA_LAUNCH_BLOCKING=1`** to synchronize after every single kernel launch, aiding identification of which kernel/transfer caused an error. \"Synchronization can be expensive; applications may run substantially slower when this environment variable is set.\"\n\n---\n\n## 2.5.5. CUDA Stream Ordering\n\n> \"Most importantly CUDA streams are what are known as in-order streams. This means that the order of execution of the operations in a stream is the same as the order in which those operations were enqueued.\"\n\nAn operation cannot leap-frog others. Memory operations (copies) are tracked by the runtime and always complete before the next operation, ensuring dependent kernels get safe access to transferred data.\n\nSemantics may be relaxed for performance in special cases:\n- **programmatic dependent kernel launch** (overlaps two kernels via special attributes/launch mechanisms)\n- **asynchronous batched memory copy functions** (runtime may perform non-overlapping batch copies concurrently)\n\n---\n\n## 2.5.6. Blocking and Non-blocking Streams and the Default Stream\n\n> \"the blocking and non-blocking semantics refer only to how the streams synchronize with the default stream.\"\n\nBy default, streams from `cudaStreamCreate()` are **blocking**. Non-blocking streams require **`cudaStreamCreateWithFlags()`** with the **`cudaStreamNonBlocking`** flag:\n```c\ncudaStream_t stream;\ncudaStreamCreateWithFlags(&stream, cudaStreamNonBlocking);\n```\nNon-blocking streams are destroyed with `cudaStreamDestroy()` as usual.\n\n### 2.5.6.1. Legacy Default Stream\n\nThe default stream (a.k.a. NULL stream / stream ID 0) is used when no stream is specified in kernel launches or blocking `cudaMemcpy()` calls. It is shared among all host threads and is a **blocking stream**. An operation launched into the default stream synchronizes with all other blocking streams — it waits for all other blocking streams to complete before executing.\n\nExample showing serialization:\n```c\ncudaStream_t stream1, stream2;\ncudaStreamCreate(&stream1);\ncudaStreamCreate(&stream2);\n\nkernel1<<<grid, block, 0, stream1>>>(...);\nkernel2<<<grid, block>>>(...);           // default stream\nkernel3<<<grid, block, 0, stream2>>>(...);\n\ncudaDeviceSynchronize();\n```\n> \"kernel2 will wait for kernel1 to complete, and kernel3 will wait for kernel2 to complete, even if in principle all three kernels could execute concurrently.\"\n\nUsing non-blocking streams removes this synchronization, allowing all three kernels to run concurrently — but no ordering is guaranteed:\n```c\ncudaStream_t stream1, stream2;\ncudaStreamCreateWithFlags(&stream1, cudaStreamNonBlocking);\ncudaStreamCreateWithFlags(&stream2, cudaStreamNonBlocking);\n\nkernel1<<<grid, block, 0, stream1>>>(...);\nkernel2<<<grid, block>>>(...);\nkernel3<<<grid, block, 0, stream2>>>(...);\n\ncudaDeviceSynchronize();\n```\n\n### 2.5.6.2. Per-thread Default Stream\n\n**Starting in CUDA-7**, each host thread can have its own independent default stream instead of the shared legacy default stream. Enable via either:\n- nvcc compiler option **`--default-stream per-thread`**, or\n- preprocessor macro **`CUDA_API_PER_THREAD_DEFAULT_STREAM`**\n\nWith this enabled, each host thread's default stream does not synchronize like the legacy default stream; the legacy example then behaves like the non-blocking stream example.\n\n---\n\n## 2.5.7. Explicit Synchronization\n\n- **`cudaDeviceSynchronize()`** — waits until all preceding commands in all streams of all host threads have completed.\n- **`cudaStreamSynchronize()`** — takes a stream; waits until all preceding commands in that stream have completed. Synchronizes the host with a specific stream, letting other streams continue on the device.\n- **`cudaStreamWaitEvent()`** — takes a stream and an event; makes all commands added to the stream **after** the call delay execution until the given event has completed.\n- **`cudaStreamQuery()`** — lets applications know if all preceding commands in a stream have completed.\n\n---\n\n## 2.5.8. Implicit Synchronization\n\n> \"Two operations from different streams cannot run concurrently if any CUDA operation on the NULL stream is submitted in-between them, unless the streams are non-blocking streams (created with the `cudaStreamNonBlocking` flag).\"\n\nGuidelines to improve concurrent kernel execution:\n- \"All independent operations should be issued before dependent operations,\"\n- \"Synchronization of any kind should be delayed as long as possible.\"\n\n---\n\n## 2.5.9.
