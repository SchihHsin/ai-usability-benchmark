Related: **CUDA Graphs** (defining a graph of async operations up front for repeated low-overhead execution).\n\n---\n\n## 2.5.2 CUDA Streams\n\nA **stream** is a work-queue abstraction for a sequence of operations (kernel launches, memory copies). Operations execute **in-order** (FIFO). Multiple streams may be used simultaneously; the runtime schedules work based on GPU resource availability. Streams may have **priorities** (a scheduling hint only, no ordering guarantee).\n\n### 2.5.2.1 Creating and Destroying Streams\n\n```cpp\ncudaStream_t stream;        // Stream handle\ncudaStreamCreate(&stream);  // Create a new stream\n\n// stream based operations ...\n\ncudaStreamDestroy(stream);  // Destroy the stream\n```\n\n> `cudaStreamDestroy()` lets the stream **complete all pending work** before destruction.\n\n### 2.5.2.2 Launching Kernels in Streams\n\n```cpp\nkernel<<<grid, block, shared_mem_size, stream>>>(...);\n```\n\nThe launch is asynchronous; the host can do other work on CPU or in other GPU streams.\n\n### 2.5.2.3 Launching Memory Transfers (`cudaMemcpyAsync`)\n\n```cpp\n// Copy `size` bytes from `src` to `dst` in stream `stream`\ncudaMemcpyAsync(dst, src, size, cudaMemcpyHostToDevice, stream);\n```\n\nUnlike `cudaMemcpy()` (which blocks), this returns immediately. Synchronization is required before accessing results. Other transfer functions (e.g., `cudaMemcpy2D()`) also have async variants.\n\n> **⚠️ Pinned vs. Pageable Memory (key note):** For memory copies involving CPU memory to run asynchronously, host buffers must be **pinned and page-locked**. `cudaMemcpyAsync()` works with non-pinned memory but **reverts to synchronous behavior** that won't overlap with other work — inhibiting performance. **Recommendation**: use `cudaMallocHost()` to allocate host buffers for GPU data transfer.\n\n### 2.5.2.4 Stream Synchronization\n\n**Blocking** — `cudaStreamSynchronize()`:\n\n```cpp\n// Wait for the stream to be empty of tasks\ncudaStreamSynchronize(stream);\n\n// At this point the stream is done\n// and we can access the results of stream operations safely\n```\n\n**Non-blocking** — `cudaStreamQuery()`:\n\n```cpp\n// returns cudaSuccess if the stream is empty\n// returns cudaErrorNotReady if the stream is not empty\ncudaError_t status = cudaStreamQuery(stream);\n\nswitch (status) {\n    case cudaSuccess:\n        std::cout << \"The stream is empty\" << std::endl;\n        break;\n    case cudaErrorNotReady:\n        std::cout << \"The stream is not empty\" << std::endl;\n        break;\n    default:\n        // An error occurred - we should handle this\n        break;\n};\n```\n\n---\n\n## 2.5.3 CUDA Events\n\nEvents are **markers inserted into streams** — like \"tracer particles\" tracking progress. They enable fine-grained dependencies (e.g., waiting for kernel 1 to finish *before* kernel 2 completes) and build **dependency graphs** between operations/streams. They also record **timestamps** for timing.\n\n### 2.5.3.1 Creating and Destroying Events\n\n```cpp\ncudaEvent_t event;\n\ncudaEventCreate(&event);\n// do some work involving the event\ncudaEventDestroy(event);\n```\n\nThe application is responsible for destroying events.\n\n### 2.5.3.2 Inserting Events into Streams\n\n```cpp\ncudaEvent_t event;\ncudaStream_t stream;\n\ncudaEventCreate(&event);\ncudaEventRecord(event, stream);   // Insert the event into the stream\n```\n\n### 2.5.3.3 Timing Operations in Streams\n\n```cpp\ncudaStream_t stream;\ncudaStreamCreate(&stream);\n\ncudaEvent_t start;\ncudaEvent_t stop;\ncudaEventCreate(&start);\ncudaEventCreate(&stop);\n\ncudaEventRecord(start, stream);                    // record start\nkernel<<<grid, block, 0, stream>>>(...);           // launch kernel\ncudaEventRecord(stop, stream);                     // record stop\n\ncudaStreamSynchronize(stream);                     // both events triggered\n\nfloat elapsedTime;\ncudaEventElapsedTime(&elapsedTime, start, stop);\nstd::cout << \"Kernel execution time: \" << elapsedTime << \" ms\" << std::endl;\n\ncudaEventDestroy(start);\ncudaEventDestroy(stop);\ncudaStreamDestroy(stream);\n```\n\n### 2.5.3.4 Checking Event Status\n\n**Blocking** — `cudaEventSynchronize()` waits until the event completes (here: kernel 1 guaranteed done, then launch a dependent CPU task while kernel 2 may still run):\n\n```cpp\ncudaEvent_t event;\ncudaStream_t stream;\n\ncudaStreamCreate(&stream);\ncudaEventCreate(&event);\n\nkernel<<<grid, block, 0, stream>>>(...);\ncudaEventRecord(event, stream);\nkernel2<<<grid, block, 0, stream>>>(...);\n\n// Kernel 1 guaranteed complete; launch dependent task\ncudaEventSynchronize(event);\ndependentCPUtask();\n\n// Kernel 2 guaranteed complete\ncudaStreamSynchronize(stream);\n\ncudaEventDestroy(event);\ncudaStreamDestroy(stream);\n```\n\n**Non-blocking (polling)** — `cudaEventQuery()`. This example demonstrates **overlap of CPU work + GPU kernel execution + device-to-host copy**: kernel1 produces data; an event follows it; kernel2 runs after; the CPU polls the event and launches the D2H copy in a *second* stream once kernel1 finishes:\n\n```cpp\ncudaEvent_t event;\ncudaStream_t stream1;\ncudaStream_t stream2;\n\nsize_t size = LARGE_NUMBER;\nfloat* d_data;\nfloat* h_data;\n\ncudaMalloc(&d_data, size);\ncudaMallocHost(&h_data, size);          // pinned host buffer\n\ncudaStreamCreate(&stream1);   // Processing stream\ncudaStreamCreate(&stream2);   // Copying stream\nbool copyStarted = false;\n\ncudaEventCreate(&event);\n\nkernel1<<<grid, block, 0, stream1>>>(d_data, size);\ncudaEventRecord(event, stream1);        // event after kernel1\nkernel2<<<grid, block, 0, stream1>>>();\n\n// Overlap CPU work with GPU work; peek for kernel1 completion\nwhile ( not allCPUWorkDone() || not copyStarted ) {\n    doNextChunkOfCPUWork();\n\n    if ( not copyStarted ) {\n        if( cudaEventQuery(event) == cudaSuccess ) {\n            cudaMemcpyAsync(h_data, d_data, size, cudaMemcpyDeviceToHost, stream2);\n            copyStarted = true;\n        }\n    }\n}\n\ncudaStreamSynchronize(stream1);\ncudaStreamSynchronize(stream2);\n\ncudaEventDestroy(event);\ncudaStreamDestroy(stream1);\ncudaStreamDestroy(stream2);\ncudaFree(d_data);\nfree(h_data);\n```\n\n---\n\n## 2.5.4 Callback Functions from Streams\n\nTwo functions launch host functions from a stream: **`cudaLaunchHostFunc()`** (preferred) and **`cudaStreamAddCallback()`** (**slated for deprecation**).\n\n### `cudaLaunchHostFunc()`\n\n```cpp\ncudaError_t cudaLaunchHostFunc(cudaStream_t stream, void (*func)(void *), void *data);\n```\n\n- `stream` — target stream; `func` — callback; `data` — user data pointer\n\nCallback signature:\n\n```cpp\nvoid hostFunction(void *data);\n```\n\n**Caveat**: the host function **may not call any CUDA APIs**.\n\n**Execution guarantees (relevant to unified memory):**\n- The stream is considered **idle** during the function's execution — it may use memory attached to its stream.\n- The function's start has the same effect as synchronizing an event recorded just before it (synchronizes \"joined\" streams).\n- Adding device work to any stream does **not** make the stream active until all preceding host functions/callbacks have executed.\n- Function completion doesn't make the stream active except as above; the stream stays idle across consecutive host functions without interleaved device work (enabling stream sync by signaling from a host function at stream end).\n\n### 2.5.4.1 `cudaStreamAddCallback()` (deprecated)\n\n```cpp\ncudaError_t cudaStreamAddCallback(cudaStream_t stream, cudaStreamCallback_t callback, void* userData, unsigned int flags);\n```\n\n- `flags` must currently be **0**.\n\nCallback signature:\n\n```cpp\nvoid callbackFunction(cudaStream_t stream, cudaError_t status, void *userData);\n```\n\n`status` carries the stream's current error state. Same restrictions: stream stays inactive until the callback completes; no CUDA calls inside.\n\n### 2.5.4.2 Asynchronous Error Handling\n\nStream errors may not surface until synchronization. Two query functions:\n\n- **`cudaGetLastError()`** — returns **and clears** the last error in the current context (a second immediate call returns `cudaSuccess` if nothing new occurred)\n- **`cudaPeekAtLastError()`** — returns the last error **without clearing**\n\nBoth return `cudaError_t`; printable names via `cudaGetErrorName()` / `cudaGetErrorString()`:\n\n```cpp\ncudaStreamSynchronize(stream);\n\n// Peek without clearing\ncudaError_t err = cudaPeekAtLastError();\nif (err != cudaSuccess) {\n    printf(\"Error with name: %s\\n\", cudaGetErrorName(err));\n    printf(\"Error description: %s\\n\", cudaGetErrorString(err));\n}\n\n// Get and clear\ncudaError_t err2 = cudaGetLastError();\nif (err2 != cudaSuccess) {\n    printf(\"Error with name: %s\\n\", cudaGetErrorName(err2));\n    printf(\"Error description: %s\\n\", cudaGetErrorString(err2));\n}\n\nif (err2 != err) {\n    printf(\"As expected, cudaPeekAtLastError() did not clear the error\\n\");\n}\n\ncudaError_t err3 = cudaGetLastError();\nif (err3 == cudaSuccess) {\n    printf(\"As expected, cudaGetLastError() cleared the error\\n\");\n}\n```\n\n> **💡 Debugging tip**: Set environment variable **`CUDA_LAUNCH_BLOCKING=1`** to synchronize after every kernel launch — helps pinpoint which kernel/transfer caused an error. Note: this can make applications run **substantially slower**.\n\n---\n\n## 2.5.5 CUDA Stream Ordering\n\nCUDA streams are **in-order streams**: execution order matches enqueue order; operations cannot leap-frog each other. Memory operations are tracked by the runtime and complete before the next operation, giving dependent kernels safe data access.\n\n**Exceptions (relaxed semantics for optimization):**\n- **Programmatic dependent kernel launch** — overlapping two kernels via special attributes\n- **Asynchronous batched memory copy** — runtime may perform non-overlapping batch copies concurrently\n\n---\n\n## 2.5.6 Blocking/Non-Blocking Streams and the Default Stream\n\nTwo stream types; the terms refer **only to synchronization with the default stream**. `cudaStreamCreate()` produces **blocking** streams by default. Create non-blocking with:\n\n```cpp\ncudaStream_t stream;\ncudaStreamCreateWithFlags(&stream, cudaStreamNonBlocking);\n```\n\nDestroy normally with `cudaStreamDestroy()`.\n\n### 2.5.6.1 Legacy Default Stream (NULL stream / stream ID 0)\n\nUsed when no stream is specified (kernel launches, blocking `cudaMemcpy()`). Shared among all host threads; it is a **blocking** stream — an operation in it **synchronizes with all other blocking streams** (waits for them to complete first).\n\n**With blocking streams — serialized execution** (kernel2 waits for kernel1; kernel3 waits for kernel2, even though all could run concurrently):\n\n```cpp\ncudaStream_t stream1, stream2;\ncudaStreamCreate(&stream1);\ncudaStreamCreate(&stream2);\n\nkernel1<<<grid, block, 0, stream1>>>(...);\nkernel2<<<grid, block>>>(...);              // default stream\nkernel3<<<grid, block, 0, stream2>>>(...);\n\ncudaDeviceSynchronize();\n```\n\n**With non-blocking streams — potential full concurrency** (default stream no longer synchronizes; no execution ordering can be assumed → explicit sync needed):\n\n```cpp\ncudaStream_t stream1, stream2;\ncudaStreamCreateWithFlags(&stream1, cudaStreamNonBlocking);\ncudaStreamCreateWithFlags(&stream2, cudaStreamNonBlocking);\n\nkernel1<<<grid, block, 0, stream1>>>(...);\nkernel2<<<grid, block>>>(...);\nkernel3<<<grid, block, 0, stream2>>>(...);\n\ncudaDeviceSynchronize();\n```\n\n### 2.5.6.2 Per-thread Default Stream (since CUDA 7)\n\nEach host thread gets its own independent default stream via:\n- nvcc option: **`--default-stream per-thread`**, or\n- Preprocessor macro: **`CUDA_API_PER_THREAD_DEFAULT_STREAM`**\n\nBehavior then matches the non-blocking stream example (no cross-stream serialization with the default stream).\n\n---\n\n## 2.5.7 Explicit Synchronization\n\n| Function | Behavior |\n|---|---|\n| `cudaDeviceSynchronize()` | Waits for **all** preceding commands in **all streams of all host threads** |\n| `cudaStreamSynchronize(stream)` | Waits for all preceding commands in the **given stream** (other streams keep running) |\n| `cudaStreamWaitEvent(stream, event)` | Commands added to `stream` after this call **delay until `event` completes** (cross-stream dependency) |\n| `cudaStreamQuery(stream)` | Reports whether all preceding commands in a stream have completed |\n\n---\n\n## 2.5.8 Implicit Synchronization\n\nOperations from different streams **cannot run concurrently** if any operation on the NULL stream is submitted between them — **unless** the streams are non-blocking (`cudaStreamNonBlocking`).\n\n**Guidelines for maximizing concurrent kernel execution:**\n1. Issue all **independent operations before dependent** ones\n2. **Delay synchronization** as long as possible\n\n---\n\n## 2.5.9 Miscellaneous and Advanced Topics\n\n### 2.5.9.1 Stream Prioritization\n\nCreated via `cudaStreamCreateWithPriority()`. **Lower numbers = higher priority.** Query range with `cudaDeviceGetStreamPriorityRange()`. Default priority is **0**.\n\n```cpp\nint minPriority, maxPriority;\n\ncudaDeviceGetStreamPriorityRange(&minPriority, &maxPriority);\n\n// cudaStreamDefault = blocking w.r.t. legacy default stream\n// (cudaStreamNonBlocking also allowed)\ncudaStream_t stream1, stream2;\ncudaStreamCreateWithPriority(&stream1, cudaStreamDefault, minPriority);  // Lowest priority\ncudaStreamCreateWithPriority(&stream2, cudaStreamDefault, maxPriority);  // Highest priority\n```\n\n> Priority is only a **hint**, applies mainly to **kernel launches** (may not be respected for memory transfers), does **not preempt** running work, and guarantees no execution order.\n\n### 2.5.9.2 Introduction to CUDA Graphs with Stream Capture\n\nMultiple streams + `cudaStreamWaitEvent` can express a full **DAG** of operations. For DAGs executed many times, **CUDA Graphs** reduce launch latency/CPU overhead:\n\n1. **Capture** the graph (once) — or compose manually via the graph API\n2. **Instantiate** (once) — sets up runtime structures for fastest launch\n3. **Execute** repeatedly with minimized CPU overhead\n\n```cpp\n#define N 500000 // tuned such that kernel takes a few microseconds\n\n__global__ void shortKernel(float * out_d, float * in_d){\n    int idx=blockIdx.x*blockDim.x+threadIdx.x;\n    if(idx<N) out_d[idx]=1.23*in_d[idx];\n}\n\nbool graphCreated=false;\ncudaGraph_t graph;\ncudaGraphExec_t instance;\n\nfor(int istep=0; istep<NSTEP; istep++){\n    if(!graphCreated){\n        // Capture the graph\n        cudaStreamBeginCapture(stream, cudaStreamCaptureModeGlobal);\n\n        for(int ikrnl=0; ikrnl<NKERNEL; ikrnl++){\n            shortKernel<<<blocks, threads, 0, stream>>>(out_d, in_d);\n        }\n\n        cudaStreamEndCapture(stream, &graph);\n\n        // Instantiate the graph\n        cudaGraphInstantiate(&instance, graph, NULL, NULL, 0);\n        graphCreated=true;\n    }\n\n    cudaGraphLaunch(instance, stream);   // Launch the graph\n    cudaStreamSynchronize(stream);       // Synchronize\n}\n```\n\n---\n\n## 2.5.10 Summary of Asynchronous Execution\n\n> - Async APIs express concurrent/overlapping execution; actual concurrency depends on hardware resources and compute capability.\n> - Key abstractions: **streams, events, callback functions**.\n> - Synchronization possible at **event, stream, and device** level.\n> - The **default stream is blocking** — synchronizes with all blocking streams, but not with non-blocking streams.\n> - Default-stream behavior avoidable via per-thread default streams (`--default-stream per-thread` or `CUDA_API_PER_THREAD_DEFAULT_STREAM`).\n> - Stream **priorities** are hints; may not apply to memory transfers.\n> - Overhead-reduction APIs: **CUDA Graphs, Batched Memory Transfers, Programmatic Dependent Kernel Launch**.\n\n---\n\n## Extraction Notes\n\n- **Completeness**: The supplied page content is intact from heading 2.5.1 through the 2.5.10 summary — a natural document endpoint. **No truncation found.** All 10 code listings present in the source were captured above.\n- **Figure reference**: The page includes \"Figure 20: Asynchronous Concurrent Execution with CUDA streams\" (image `cuda_streams.png`) — image content not available as text.\n- **Cross-references** on the page (not expanded here): Compute Capabilities appendix;
