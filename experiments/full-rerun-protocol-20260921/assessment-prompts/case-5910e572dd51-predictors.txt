Adding `torch.compile` Support (FakeTensor / Meta Kernel)\n\nTo add `torch.compile` support, add a **FakeTensor kernel** (a.k.a. \"meta kernel\" or \"abstract impl\"). FakeTensors have metadata (shape, dtype, device) but no data; the kernel computes output metadata from input metadata and should return dummy Tensors with correct metadata (shape/strides/dtype/device).\n\nRecommended via Python `torch.library.register_fake` (possible from C++ too — see the Custom Operators Manual).\n\n```python\n# Important: the C++ custom operator definitions should be loaded first\n# before calling ``torch.library`` APIs that add registrations for the\n# C++ custom operator(s). The following import loads our\n# C++ custom operator definitions.\n# Note that if you are striving for Python agnosticism, you should use\n# the ``load_library(...)`` API call instead. See the next section for\n# more details.\nfrom . import _C\n\n@torch.library.register_fake(\"extension_cpp::mymuladd\")\ndef _(a, b, c):\n    torch._check(a.shape == b.shape)\n    torch._check(a.dtype == torch.float)\n    torch._check(b.dtype == torch.float)\n    torch._check(a.device == b.device)\n    return torch.empty_like(a)\n```\n\n---\n\n## 7. Hybrid Python/C++ Registration (Loading Order)\n\nThe tutorial defines a custom operator in C++, adds CPU/CUDA implementations in C++, and adds FakeTensor kernels and backward formulas in Python. **Registration/import order matters** (wrong order → error). Must first load the C++ library holding the operator definition, then call `torch.library` registration APIs. Three ways:\n\n### Way 1 — `PYBIND11_MODULE` dummy module (breaks CPython agnosticism)\n\n```cpp\n// in, say, not_agnostic/csrc/extension_BAD.cpp\n#include <pybind11/pybind11.h>\n\nPYBIND11_MODULE(\"_C\", m) {}\n```\n```python\n# in, say, extension/__init__.py\nfrom . import _C\n```\n\n> \"...you will notice that this does not compile with `Py_LIMITED_API`, because `pybind11` does not promise to only use the stable limited CPython API! With the below code, you sadly cannot build a CPython agnostic wheel for your extension!\"\n\n### Way 2 — Stable API dummy `_C` module (recommended; compiles with `-DPy_LIMITED_API=0x03090000`)\n\n> See [extension_cpp/__init__.py](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/__init__.py) and [extension_cpp/csrc/muladd.cpp](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/csrc/muladd.cpp).\n\n```cpp\n#include <Python.h>\n\nextern \"C\" {\n  /* Creates a dummy empty _C module that can be imported from Python.\n    The import from Python will load the .so consisting of this file\n    in this extension, so that the TORCH_LIBRARY static initializers\n    below are run. */\n  PyObject* PyInit__C(void)\n  {\n      static struct PyModuleDef module_def = {\n          PyModuleDef_HEAD_INIT,\n          \"_C\",   /* name of module */\n          NULL,   /* module documentation, may be NULL */\n          -1,     /* size of per-interpreter state of the module,\n                    or -1 if the module keeps state in global variables. */\n          NULL,   /* methods */\n      };\n      return PyModule_Create(&module_def);\n  }\n}\n```\n```python\nfrom . import _C\n```\n\n### Way 3 — `torch.ops.load_library` (avoids `Python.h` entirely)\n\n> \"Note that, with this method, there is no `_C` Python module created for the extension so you cannot call `import _C` from Python.\"\n\n```python\nimport torch\nfrom pathlib import Path\n\nso_files = list(Path(__file__).parent.glob(\"_C*.so\"))\nassert (\n    len(so_files) == 1\n), f\"Expected one _C*.so file, found {len(so_files)}\"\ntorch.ops.load_library(so_files[0])\n\nfrom . import ops\n```\n\n---\n\n## 8. Adding Training (Autograd) Support\n\nUse `torch.library.register_autograd`. Prefer this over directly using Python `torch.autograd.Function` (see the Custom Operators Manual).\n\n```python\ndef _backward(ctx, grad):\n    a, b = ctx.saved_tensors\n    grad_a, grad_b = None, None\n    if ctx.needs_input_grad[0]:\n        grad_a = grad * b\n    if ctx.needs_input_grad[1]:\n        grad_b = grad * a\n    return grad_a, grad_b, None\n\ndef _setup_context(ctx, inputs, output):\n    a, b, c = inputs\n    saved_a, saved_b = None, None\n    if ctx.needs_input_grad[0]:\n        saved_b = b\n    if ctx.needs_input_grad[1]:\n        saved_a = a\n    ctx.save_for_backward(saved_a, saved_b)\n\n# This code adds training support for the operator. Creating Mutable Operators\n\n> \"You may wish to author a custom operator that mutates its inputs. Use `Tensor(a!)` to specify each mutable Tensor in the schema; otherwise, there will be undefined behavior. If there are multiple mutated Tensors, use different names (for example, `Tensor(a!)`, `Tensor(b!)`, `Tensor(c!)`) for each mutable Tensor.\"\n\nExample `myadd_out(a, b, out)` operator, writing `a+b` into `out`.\n\n### ABI-Stable LibTorch API\n\n```cpp\nvoid myadd_out_cpu(\n    const torch::stable::Tensor& a,\n    const torch::stable::Tensor& b,\n    torch::stable::Tensor& out) {\n  STD_TORCH_CHECK(a.sizes().equals(b.sizes()));\n  STD_TORCH_CHECK(b.sizes().equals(out.sizes()));\n  STD_TORCH_CHECK(a.scalar_type() == torch::headeronly::ScalarType::Float);\n  STD_TORCH_CHECK(b.scalar_type() == torch::headeronly::ScalarType::Float);\n  STD_TORCH_CHECK(out.scalar_type() == torch::headeronly::ScalarType::Float);\n  STD_TORCH_CHECK(out.is_contiguous());\n  STD_TORCH_CHECK(a.device().type() == torch::headeronly::DeviceType::CPU);\n  STD_TORCH_CHECK(b.device().type() == torch::headeronly::DeviceType::CPU);\n  STD_TORCH_CHECK(out.device().type() == torch::headeronly::DeviceType::CPU);\n\n  torch::stable::Tensor a_contig = torch::stable::contiguous(a);\n  torch::stable::Tensor b_contig = torch::stable::contiguous(b);\n\n  const float* a_ptr = a_contig.const_data_ptr<float>();\n  const float* b_ptr = b_contig.const_data_ptr<float>();\n  float* result_ptr = out.mutable_data_ptr<float>();\n\n  for (int64_t i = 0; i < out.numel(); i++) {\n    result_ptr[i] = a_ptr[i] + b_ptr[i];\n  }\n}\n```\n\nSchema (note the `Tensor(a!)` mutation specifier on `out`):\n```cpp\nSTABLE_TORCH_LIBRARY(extension_cpp, m) {\n  m.def(\"mymuladd(Tensor a, Tensor b, float c) -> Tensor\");\n  m.def(\"mymul(Tensor a, Tensor b) -> Tensor\");\n  m.def(\"myadd_out(Tensor a, Tensor b, Tensor(a!) out) -> ()\");\n}\n\nSTABLE_TORCH_LIBRARY_IMPL(extension_cpp, CPU, m) {\n  m.impl(\"mymuladd\", TORCH_BOX(&mymuladd_cpu));\n  m.impl(\"mymul\", TORCH_BOX(&mymul_cpu));\n  m.impl(\"myadd_out\", TORCH_BOX(&myadd_out_cpu));\n}\n```\n\n### Non-ABI-Stable LibTorch API\n\n```cpp\nvoid myadd_out_cpu(const at::Tensor& a, const at::Tensor& b, at::Tensor& out) {\n  TORCH_CHECK(a.sizes() == b.sizes());\n  TORCH_CHECK(b.sizes() == out.sizes());\n  TORCH_CHECK(a.dtype() == at::kFloat);\n  TORCH_CHECK(b.dtype() == at::kFloat);\n  TORCH_CHECK(out.dtype() == at::kFloat);\n  TORCH_CHECK(out.is_contiguous());\n  TORCH_INTERNAL_ASSERT(a.device().type() == at::DeviceType::CPU);\n  TORCH_INTERNAL_ASSERT(b.device().type() == at::DeviceType::CPU);\n  TORCH_INTERNAL_ASSERT(out.device().type() == at::DeviceType::CPU);\n  at::Tensor a_contig = a.contiguous();\n  at::Tensor b_contig = b.contiguous();\n  const float* a_ptr = a_contig.data_ptr<float>();\n  const float* b_ptr = b_contig.data_ptr<float>();\n  float* result_ptr = out.data_ptr<float>();\n  for (int64_t i = 0;
