1，dimension 1）。TensorRT 在转置前量化权重。\n\n### 2.4 TensorRT Model Optimizer 与迁移建议\n\n**迁移建议（原文明确）**：\n> *\"Users are strongly advised to transition to explicit quantization, typically by utilizing the TensorRT Model Optimizer to create models with explicit quantization.\"*\n\n- [TensorRT Model Optimizer](https://github.com/NVIDIA/TensorRT-Model-Optimizer)：Python 工具包，用于创建 QAT 模型（完全兼容 TensorRT 优化与部署流程）；同时提供 **PTQ recipe**，支持 PyTorch 和 ONNX 格式模型的 PTQ。\n- **重要约束**：带 Q/DQ 节点的模型**不允许再提供外部校准表**（TensorRT 拒绝加载）。显式模型的校准必须在 **ONNX 导出之前**完成（如用 Model Optimizer 做 PTQ/QAT），scale 直接嵌入 Q/DQ 节点。\n- **已知差距**：某些网络上，初始显式量化的延迟可能高于隐式量化；Model Optimizer 团队正与 TensorRT 团队协作缩小该差距。\n- QAT 支持：**TensorFlow**（Model Optimizer + TF2 Keras；注意 **TF1 不支持 per-channel quantization**）；**PyTorch**（1.8.0+ 支持 **默认不量化带权重操作的输出**（保留高精度输出，例如后接 SiLU 等激活函数时）；\n3. **不要在训练框架中模拟 batch normalization 和 ReLU 融合**（TensorRT 优化保证保留其算术语义）;\n4. **量化跳跃连接（skip connection）的残差输入**（如 ResNet、EfficientNet）：element-wise add 第一个输入的精度决定融合输出精度——残差为 FP 时尾部 Q 层无法与卷积融合；残差为 INT8 时可以；\n5. 为获得额外性能，可尝试量化不与 Q/DQ 交换的层（当前非带权重层若 INT8 输入则也要求 INT8 输出，输入输出都要量化）；\n6. **保守地添加 Q/DQ 节点**，兼顾精度与性能实验——多余的 Q/DQ 会导致次优融合；\n7. **激活用 per-tensor 量化，权重用 per-channel 量化**（经验上精度最佳）；\n8. 可通过**启用 FP16** 进一步优化延迟（TensorRT 尽可能用 FP16 替代 FP32，并非所有层类型都支持）——这是所给内容中与 \"kFp16\" 最接近的表述，**未给出具体 flag 代码**。\n9. 旧设备可能缺少部分层的低精度 kernel 实现，构建时报 `could not find any
