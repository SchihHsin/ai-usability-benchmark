定义算子：TORCH_LIBRARY 用法与 Schema 定义\n\n定义算子的步骤：\n1. 为算子选择命名空间，推荐使用顶层项目名；本教程使用 `\"extension_cpp\"`\n2. 提供一个 schema 字符串，指定算子的输入/输出类型以及输入 Tensor 是否会被 mutate（变更）。除 Tensor 和 float 外还支持更多类型，详见 [The Custom FakeTensor kernel 指定如何由输入元数据计算输出元数据，应返回具有正确 Tensor 元数据的 dummy Tensor。\n\n推荐从 Python 通过 `torch.library.register_fake` API 完成（C++ 亦可，详见 [The Custom Operators Manual](https://pytorch.org/docs/main/notes/custom_operators.html)）：\n```python\n# Important: the C++ custom operator definitions should be loaded first\n# before calling ``torch.library`` APIs that add registrations for the\n# C++ custom operator(s). The following import loads our\n# C++ custom operator definitions.\n# Note that if you are striving for Python agnosticism, you should use\n# the ``load_library(...)`` API call instead. See the next section for\n# more details.\nfrom . import _C\n\n@torch.library.register_fake(\"extension_cpp::mymuladd\")\ndef _(a, b, c):\n    torch._check(a.shape == b.shape)\n    torch._check(a.dtype == torch.float)\n    torch._check(b.dtype == torch.float)\n    torch._check(a.device == b.device)\n    return torch.empty_like(a)\n```\n\n---\n\n## 5. 混合 Python/C++ 注册：三种加载方式\n\n本教程在 C++ 中定义算子、添加 CPU/CUDA 实现，在 Python 中添加 FakeTensor kernel 和 backward 公式。**这些注册的加载（导入）顺序很重要**（顺序错误会报错）：必须先加载持有算子定义的 C++ 库，再调用 `torch.library` 注册 CPython API，因此**无法用 `Py_LIMITED_API` 编译**，即无法构建 CPython 无关 wheel：\n\n```cpp\n// in, say, not_agnostic/csrc/extension_BAD.cpp\n#include <pybind11/pybind11.h>\n\nPYBIND11_MODULE(\"_C\", m) {}\n```\n```python\n# in, say, extension/__init__.py\nfrom . import _C\n```\n\n**方式二（stable API 版 dummy 模块）：** 用稳定 API 调用替换不稳定的 `PYBIND11` 调用。以下代码可用 `-DPy_LIMITED_API=0x03090000` 编译，成功创建可从 Python 导入的 `_C` dummy 模块（详见 [extension_cpp/__init__.py](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/__init__.py) 与 [extension_cpp/csrc/muladd.cpp](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/csrc/muladd.cpp)）：\n```cpp\n#include <Python.h>\n\nextern \"C\" {\n  /* Creates a dummy empty _C */\n  PyObject* PyInit__C(void)\n  {\n      static struct PyModuleDef module_def = {\n          PyModuleDef_HEAD_INIT,\n          \"_C\",   /* name of module */\n          NULL,   /* module documentation, may be NULL */\n          -1,     /* size of per-interpreter state of the module,\n                    or -1 if the module keeps state in global variables. */\n          NULL,   /* methods */\n      };\n      return PyModule_Create(&module_def);\n  }\n}\n```\n```python\nfrom . import _C\n```\n\n**方式三（torch.ops.load_library，完全避免 Python.h）：** 用 `torch.ops.load_library(\"/path/to/library.so\")` 加载扩展编译出的 `.so` 文件。此方式不会创建 `_C` Python 模块，因此不能 `import _C`；不再依赖 import 语句触发注册，而是由 `torch.ops.load_library` 完成。难点在于定位 `.so`
