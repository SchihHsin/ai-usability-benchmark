**dump.json**：保存API或Module前反向数据的统计量信息，包含数据名称、dtype、shape、max、min、mean、L2norm（L2范数，平方根），以及根据`summary_mode`输出的校验值（`md5`对应CRC-32字段，`xor`对应XOR校验字段）。\n  - `task=\"nan_check\"`时，各API数据包含`is_nan`字段（0代表无溢出，1代表有溢出；该模式下不保存统计值）。\n- **dump_error_info.log**：仅在dump工具报错时生成，记录dump错误日志。\n- **stack.json**：API/Module的调用栈信息。\n- **construct.json**：分层分级结构；level为L1时内容为空。\n\n**落盘机制**：pt文件在对应算子/模块被执行后就落盘；json文件需在正常执行`PrecisionDebugger.stop()`后才写入完整数据。异常终止的程序会保存终止前已执行算子的相关pt文件，可能导致json文件数据丢失。\n\n**pt文件前缀与PyTorch对应关系**：\n\n| 前缀 | API输入输出过滤\n\n**功能说明**：msProbe提供固定API支持列表（见`support_wrap_ops.yaml`）。若不需要采集这些API的部分输入或输出，可在`builtin_ignore_ops.yaml`文件中配置内置忽略规则。命中忽略规则后，工具保留API调用记录但屏蔽其输入/输出，对应位置在dump结果中置为`Null`。该功能通常用于通信算子的接收缓冲区、原地写入类输出等不需要参与精度比对的参数。\n\n- 若目标是**完全不采集某个API** → 修改`support_wrap_ops.yaml`\n- 若目标是**保留API调用记录但屏蔽部分输入/输出** → 修改`builtin_ignore_ops.yaml`\n\n**注意事项**：当前仅支持配置 API forward 调用的输入或输出忽略规则，不支持配置 API backward。这里的 API forward 调用指 API 的 forward 方法调用，不等同于训练脚本中的 forward 阶段。\n\n**配置格式**：\n```yaml\n{一级键}:\n  {二级键}:\n    input: [{input1}, {input2}...]\n    output: [{output1}, {output2}...]\n```\n\n**字段说明**：\n- **一级键**：顶层分类，填写冒号前的分类名称，使用dump结果中的API前缀（大小写需一致）\n- **二级键**：API名称，填写去掉顶层分类后的API名称（如dump结果为`Distributed.recv.0.forward`时填写`recv`；若API名称本身包含`.`需保留完整名称）\n- **input**：需忽略的API forward输入。列表中的整数表示位置参数下标，字符串表示关键字参数名；也可配置为`all`忽略全部输入\n- **output**：需忽略的API forward输出。列表中的整数表示输出下标；也可配置为`all`忽略全部输出\n\n**顶层分类对应关系表**：\n\n| support_wrap_ops.yaml | builtin_ignore_ops.yaml |\n|---|---|\n| `functional` | `Functional` |\n| `tensor` | `Tensor` |\n| `torch` | `Torch` |\n| `_VF` | `VF` |\n| `torch_npu` | `NPU` |\n| `aten` | `Aten` |\n| `distributed` | `Distributed` |\n| `npu_distributed` | `Distributed` |\n| `mindspeed` | `MindSpeed` |\n\n**配置示例**：\n```yaml\n# 忽略torch.distributed.recv第0个输入参数tensor\nDistributed:\n  recv:\n    input: [0]\n\n# 忽略torch.distributed.isend全部输出\nDistributed:\n  isend:\n    output: all\n\n# 忽略torch_npu.npu_fusion_attention第4、5个输出\nNPU:\n  npu_fusion_attention:\n    output: [4, 5]\n```\n\n修改该文件后需重新启动训练或推理进程，使配置重新加载。\n\n### 7.2 采集随机性API（random_save）\n\n**功能说明**：寻找模型脚本中所有随机性API的调用位置，结果输出到csv表格。\n\n**使用示例**：\n```python\n import torch\n import torch.nn as nn\n import torch.nn.functional as F\n\n# 导入工具寻找随机性API的接口，网络中的随机性API会被保存在output路径下。\nfrom msprobe.pytorch import random_save\nrandom_save(output_path=\"./output\")\n\n# 定义网络\nclass ModuleOP(nn.Module):\n    def __init__(self) -> None:\n        super().__init__()\n        self.linear = nn.Linear(in_features=8, out_features=4)\n\n    def forward(self, x):\n        x1 = self.linear(x)\n        r1 = F.relu(x1)\n        return r1\n\nif __name__ == \"__main__\":\n    model = ModuleOP()\n    x = torch.randn(10, 8)\n    out = model(x)\n    loss = out.sum()\n    loss.backward()\n```\n\n**输出说明**：执行完成后在output_path下生成csv文件。有rank信息时文件名为`random_rank{id}_{timestamp}.csv`，否则为`random_proc{pid}_{timestamp}.csv`。csv内容包括：\n- **api_name**：模型脚本中随机性API的名称\n- **stack**：随机性API对应的堆栈信息\n\n### 7.3 批量注册用户自定义的API\n\n**功能说明**：除逐个调用`register_custom_api`外，支持通过YAML配置文件批量自动注册自定义API，适用于需注册大量自定义算子的场景。\n\n**注意事项**：在msprobe工具安装目录下的`pytorch/dump/api_dump/`目录中修改`custom_wrap_ops.yaml`文件，勿改文件名。修改后需重启训练/推理进程使配置重新加载。\n\n**配置格式**：\n```yaml\n<模块路径>:\n  - <API名称1>\n  - <API名称2>\n```\n\n**字段说明**：\n- **模块路径**：API所属的Python模块路径，支持多级子模块（如`torch.nn.functional`、`module_a.submodule`），必须是有效Python模块路径（字母、数字、下划线和点号组成，首字符为字母或下划线）。默认为dump.json中API名的前缀\n- **API名称**：模块中需注册的API属性名（如`relu`、`compute`），必须是有效Python标识符\n\n**配置示例**：\n```yaml\n# 注册主函数中的API\n__main__:\n  - add_and_mul\n```\n\n例如：\n```python\nimport torch\n\ndef add_and_mul(a, b, c):\n    \"\"\"计算 (a + b) * c\"\"\"\n    return (a + b) * c\n# 在此使能工具后，默认 dump 已经注册 add_and_mul\n```\n\n---\n\n## 八、接口介绍（API使用方式）\n\n### 8.1 PrecisionDebugger\n\n**功能说明**：通过加载dump配置文件的方式确定dump操作的详细配置。此接口的初始化需与采集目标在同一个进程中，否则将无法采集目标数据。\n\n**函数原型**：\n```python\ndebugger = PrecisionDebugger(config_path=None, task=None, dump_path=None, level=None, step=None)\n```\n\n**参数说明**：\n- **config_path**：可选，str类型，指定dump配置文件路径（示例：\"./config.json\"）。未配置时默认使用config.json文件的默认配置（配置选项含义见《config.json介绍》）\n- 其他参数均在config.json文件中可配（详细配置见《config.json介绍》）\n- 此接口的参数均不是必要的（均不配置时默认采集所有rank和step的L1级别统计数据），且**优先级高于config.json文件中的配置**，但可配置的参数相比config.json较少\n\n**返回值**：debugger是PrecisionDebugger类的实例对象，提供start、stop和step等函数开启和结束数据采集的功能。\n\n### 8.2 start\n\n**功能说明**：启动精度数据采集。在模型初始化之后的位置添加。需要与stop和step等函数一起搭配使用。\n\n**函数原型**：\n```python\ndebugger.start(model=None, token_range=None, rank_id=None, scheduled_tokens=None)\n```\n\n**参数说明**：\n- **model**：指定需要采集Module级数据的模型，支持torch.nn.Module、list[torch.nn.Module]或Tuple[torch.nn.Module]类型，默认未配置。level配置为\"L0\"、\"mix\"或token_range不为None时，必须在该接口中配置该参数。对于复杂模型，如果仅需要监测一部分（如model.A），传入需要监测的部分即可。\n  > ⚠️ 注意：传入的当前层不会被dump，工具只会dump传入层的子层级。如传入了model.A，A本身不会被dump，而是会dump A.x, A.x.xx等。\n- **token_range**：指定推理模型采集时的token循环始末范围，支持传入[int, int]类型，代表[start, end]，范围包含边界，默认未配置。\n- **rank_id**：指定自定义的rank ID，支持传入大于等于0的整数。默认未配置，工具基于torch.distributed.get_rank接口获取rank ID；配置后，dump结果中rank文件夹名称中的{ID}将使用该参数所配置的值。\n  > 注意：通常情况下无需手动配置。特殊场景下get_rank可能返回重复rank ID（例如推理框架sglang的DP推理场景，各DP worker是独立的分布式集群），引发rank文件夹同名覆盖导致dump数据丢失。此时可配置rank_id为rank文件夹命名，需保证各进程中唯一（如sglang中的`self.gpu_id`）。配置示例：`debugger.start(rank_id=self.gpu_id)`\n- **scheduled_tokens**：指定当前调度每个请求占用的token数，dict类型。key是str（请求id），value是int且>=0（该请求占用的token数）。配置示例：`debugger.start(scheduled_tokens={\"chatcmpl-req-0\": 10, \"chatcmpl-req-1\": 15})`。配合request_id配置可实现指定请求id采集数据。\n\n### 8.3 stop\n\n**功能说明**：停止精度数据采集。在start接口之后的任意位置添加。\n- 若stop添加在反向计算代码（如loss.backward）之后，则会采集start和该函数之间的前反向数据。\n- 若stop添加在反向计算代码之前，则需要将step函数添加到反向计算代码之后，才能采集start和该函数之间的前反向数据。\n\n> ⚠️ **stop函数必须调用，否则可能导致精度数据落盘不全。**\n\n**函数原型**：`debugger.stop()`（无返回值）\n\n### 8.4 step\n\n**功能说明**：结束一个step的数据采集，完成所有数据落盘并更新dump参数。在一个step结束的位置添加，且必须在stop函数之后的位置调用。\n\n> ⚠️ 该函数需配合start和stop使用，尽量添加在反向计算代码（如loss.backward）之后，否则可能导致反向数据丢失。\n\n**函数原型**：`debugger.step()`（无返回值）\n\n### 8.5 module_dump\n\n**功能说明**：开启模块级精度数据dump。该接口为函数模块化接口，即只会dump输入的模块数据，不会dump子模块和模块内API的数据。需配合start、stop和step等接口使用。\n\n**函数原型**：\n```python\nmodule_dump(module, module_name)\n```\n- **module**：网络中实例化好的nn.Module类对象，torch.nn.Module类型，必选\n- **module_name**：用户自定义该module名称，主要用于dump数据的命名，str类型，必选\n\n### 8.6 module_dump_end\n\n**功能说明**：结束模块级精度数据dump。在module_dump和module_dump_end之间的API或Module，除了传入的module，其他数据均不会被dump。执行完module_dump_end后数据恢复正常dump模式。\n\n**函数原型**：`module_dump_end()`（无返回值）\n\n### 8.7 save\n\n**功能说明**：单点保存网络执行过程中前反向数值，并以统计值数据或张量文件落盘。\n\n**函数原型**：\n```python\nsave(variable, name, save_backward=True)\n```\n\n| 参数名称 | 可选/必选 | 参数含义 |\n|---|---|---|\n| variable | 必选 | 需要保存的变量，支持数据类型：dict, list, tuple, torch.tensor, int, float, str |\n| name | 必选 | 指定的名称，str类型 |\n| save_backward | 可选 | 是否保存反向数据，boolean类型 |\n\n### 8.8 set_init_step\n\n**功能说明**：设置起始step数。step数默认从0开始计数，使用该接口后step从指定值开始计数。该函数需写在训练迭代的循环开始前，**不能写在循环内**。\n\n**函数原型**：\n```python\ndebugger.set_init_step(step)\n```\n- **step**：指定的起始step数\n\n### 8.9 register_custom_api\n\n**功能说明**：注册用户自定义的API到工具用于API级数据dump。\n\n**函数原型**：\n```python\ndebugger.register_custom_api(module, api, api_prefix)\n```\n\n以torch.matmul api为例：\n- **module**：必选，API所属的包，即传入torch\n- **api**：必选，API的名称，str类型，即传入\"matmul\"\n- **api_prefix**：可选，dump.json中api名的前缀，默认为包名的字符串格式，即\"torch\"\n\n**调用示例**：\n```python\n# 需要导入自定义算子的模块\nimport module_a\nfrom column_name() -> str:  # 算法结果展示的列名，需要保证唯一\n    # 以下为示例\n    return \"MaxAbsError\"\n\ndef compare(n_value: torch.Tensor, b_value: torch.Tensor):  # 进行比对的算法实现\n    # 以下为示例\n    diff = torch.abs(n_value - b_value)\n    max_abs = diff.max()\n    return max_abs.item()\n```\n\n**参数说明：**\n\n| 参数名 | 说明 |\n|---|---|\n| `n_value` | target_path 侧对应的单条数据，类型是 `torch.Tensor` |\n| `b_value` | golden_path |\n| Bench Tensor Shape | Bench 张量形状 |\n| NPU Requires_grad | NPU tensor 是否计算梯度 |\n| Bench Requires_grad | Bench tensor 是否计算梯度 |\n\n**个性表头**（统计量有 4 种：最大值 max、最小值 min、平均值 mean、L2-范数 L2 norm）：\n\n| 表头 | Cosine：N·B / (‖N‖₂·‖B‖₂)\n- EucDist：‖A−B‖₂\n- MaxAbsErr：max(|N−B|)\n- MaxRelativeErr：max(RE)\n- One Thousandth Err Ratio：∑I(RE<0.001) / size(RE)\n- Five Thousandth Err Ratio：∑I(RE<0.005) / size(RE)\n\n**统计数据模式：**\n- Max diff：max(N)−max(B)\n- Min diff：min(N)−min(B)\n- Mean diff：mean(N)−mean(B)\n- L2 Norm diff：l2norm(N)−l2norm(B)\n- MaxRelativeErr：|(max(N)−max(B)) / max(B)| ∗ 100%\n- MinRelativeErr：|(min(N)−min(B)) / min(B)| ∗ 100%\n- MeanRelativeErr：|(mean(N)−mean(B)) / mean(B)| ∗ 100%\n- NormRelativeErr：|(l2norm(N)−l2norm(B)) / l2norm(B)| ∗ 100%\n\n#### 比对结果\n\n比对结果分三类：**pass、warning、error**，优先级 **error > warning > pass**。Err_message 列呈现标记原因：\n\n**error 标记情况：**\n1. 一个 API 或模块的 NPU 的最大值或最小值中存在 nan/inf/-inf，如果 Bench 指标存在相同现象则忽略（真实数据模式、统计数据模式）；\n2. One Thousandth Err Ratio 的 input/parameters > 0.9 同时 output < 0.6（真实数据模式）（仅标记 output）（使用输入进行计算）；\n3. input 的 norm 值相对误差 < 0.1 且 output 的 norm 值相对误差 > 0.5（统计数据模式）（仅标记 output）（使用输入进行计算）；\n4. Requires_grad（计算梯度）不一致（真实数据模式、统计数据模式）；\n5. 非 tensor 标量参数不一致（真实数据模式、统计数据模式）；\n6. CRC-32 值不一致（md5 模式）；\n7. dtype 不一致（真实数据模式、统计数据模式）；\n8. shape 不一致（真实数据模式、统计数据模式）。\n\n**warning 标记情况：**\n1. output 的 norm 值相对误差是 input/parameters 的 norm 值相对误差的 10 倍（统计数据模式）（仅标记 output）（使用输入进行计算）；\n2. Cosine 的 input/parameters > 0.9 且 input/parameters − output > 0.1（真实数据模式）（仅标记 output）（使用输入进行计算）；\n3. 参数未匹配（md5 模式）。\n\n**特殊场景：**\n1. 输入存在占位的 API，涉及使用输入进行计算的指标规则不适用，包括：`['_reduce_scatter_base', '_all_gather_base', 'all_to_all_single', 'batch_isend_irecv']`；\n2. 冗余 API，所有指标不适用，包括：`['empty', 'empty_like', 'numpy', 'to', 'setitem', 'empty_with_format', 'new_empty_strided', 'new_empty', 'empty_strided']`。\n\n#### 计算精度评价指标分析\n\n1. **Cosine**：计算两个向量余弦值判断相似度，数值越接近 1 越相似，实际可接受阈值为**大于 0.99**。计算中可能存在 nan，主要由于其中一个向量为 0。\n2. **EucDist**：欧氏距离，多维空间中两点间绝对距离。数值越接近 0 越相似，越大差异越大。\n3. **MaxAbsErr**：最大绝对误差越接近 0 误差越小，实际可接受阈值为**小于 0.001**。\n4. **MaxRelativeErr**：越接近 0 误差越小。当 dump 数据中存在 0 或 nan 时，比对结果中最大相对误差出现 inf 或 nan 属于正常现象。\n5. **One Thousandth / Five Thousandth Err Ratio**：NPU Tensor 中元素逐个与标杆数据对比，相对误差小于千分之一/千分之五的元素占总元素的比例。**仅作为精度下降趋势的参考，不参与精度是否通过的判定。**\n\n## 四、多卡数据汇总功能介绍\n\n### 4.1
