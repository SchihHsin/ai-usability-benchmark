elemOffset + chunkOffset;\n        nelem = (int)min(chunkCount, remCount - chunkOffset);\n        // 开始all-gather操作\n        prims.directRecvCopyDirectSend(offset, offset, nelem);\n      }\n\n      // Make final copy from buffer to dest.\n      chunk = modRanks(ringIx + 1);\n      chunkOffset = chunk * chunkCount;\n      offset = gridOffset + elemOffset + chunkOffset;\n      nelem = (int)min(chunkCount, remCount - chunkOffset);\n\n      // 完成all-gather操作\n      prims.directRecv(offset, nelem);\n    }\n  }\n```\n\n在感知到prev/next rank后，需要进行recv/send操作，当前通信组下所有rank的send/recv操作构成一次完整的集合通信。all-reduce/all-gather/reduce-scatter的区别也体现在send/recv操作的组合上。从上面代码上看，directSend + directRecvReduceDirectSend + directRecvReduceCopyDirectSend构成reduce-scatter操作，directRecvCopyDirectSend + directRecv构成all-gather操作。\n\n论文关于通信原语如何在实际通信中运行的逻辑，有一张图画的很详细，如下贴出。这是一个完整的基于NCCL_ALGO=Ring的all-reduce集合通信。首先从图中可以看出，all-reduce被分为了reduce-scatter+all-gather操作。每条连线上表示通信kernel在执行的prims操作，纯send/recv操作标记通信的冷启动和结束，中间的recv/send操作都由fused
