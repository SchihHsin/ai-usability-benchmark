CPU、CUDA）。调用算子时，dispatcher 通过查看张量参数及线程本地状态确定**最高优先级的 dispatch key**，并将控制权转移给该 key 对应的 kernel。**实际效果是：先执行 Autograd kernel，再根据设备类型 redispatch 到后端 kernel。**\n\n### 第 1 步：用 TORCH_LIBRARY 定义 Schema\n\n与简单的 pybind11 风格注册不同，此处**不提供实现**，只提供 schema 字符串（类型签名）：\n\n```cpp\nTORCH_LIBRARY(myops, m) {\n  m.def(\"myadd(Tensor self, Tensor other) -> Tensor\");\n}\n```\n\n### 第 2 步：编写 CPU 实现示例\n\n```cpp\nTensor myadd_cpu(const Tensor& self_, const Tensor& other_) {\n  TORCH_CHECK(self_.sizes() == other_.sizes());\n  TORCH_INTERNAL_ASSERT(self_.device().type() == DeviceType::CPU);\n  TORCH_INTERNAL_ASSERT(other_.device().type() == DeviceType::CPU);\n  Tensor self = self_.contiguous();\n  Tensor other = other_.contiguous();\n  Tensor result = torch::empty(self.sizes(), self.options());\n  const float* self_ptr = self.data_ptr<float>();\n  const float* other_ptr = other.data_ptr<float>();\n  float* result_ptr = result.data_ptr<float>();\n  for (int64_t i = 0; i < result.numel(); i++) {\n    result_ptr[i] = self_ptr[i] + other_ptr[i];\n  }\n  return result;\n}\n```\n\n### 第 3 步：用 TORCH_LIBRARY_IMPL 按 Dispatch Key 注册\n\n直接用 `def(\"myadd\", myadd_cpu)` 会注册为 **\"catch-all\" kernel**（对所有情况都运行，包括非 CPU 张量）。为确保 `myadd_cpu` 只在 CPU 张量上运行：\n\n```cpp\nTORCH_LIBRARY_IMPL(myops, CPU, m) {\n  m.impl(\"myadd\", myadd_cpu);\n}\n```\n\n**CUDA 实现**在单独的 block 中注册：\n\n```cpp\nTORCH_LIBRARY_IMPL(myops, CUDA, m) {\n  m.impl(\"myadd\", myadd_cuda);\n}\n```\n\n### 推荐的注册结构\n\n1. **单个 `TORCH_LIBRARY`**：在一个集中位置列出命名空间内所有自定义算子\n2. **每个 dispatch key 一个 `TORCH_LIBRARY_IMPL`**（如 CPU 或 CUDA）。还可以按算子进一步细分 block —— 如果每个算子实现一个文件、又不想在 header 中暴露算子，直接把注册代码放在定义算子的 cpp 文件中即可\n\n> 📌 **注册可跨文件、跨库边界拆分**，例如可编译为独立的 `myops_cpu` 和 `myops_cuda` 动态库。\n\n> 📝 **Note**：`TORCH_LIBRARY_IMPL` 也可用于 **PyTorch 已有的核心算子**。PyTorch 的 XLA 支持就是这么实现的：`torch_xla` 库包含一个 `TORCH_LIBRARY_IMPL`，为所有基础算子提供 XLA dispatch key 上的实现。\n\n---\n\n## 三、不需要 Autograd 的算子（PyTorch >= 1.10）\n\n为使算子行为与 PyTorch 内置算子一致，应注册如下 kernel：\n\n```cpp\nTORCH_LIBRARY_IMPL(myops, Autograd, m) {\n  m.impl(op, autogradNotImplementedFallback());\n}\n```\n\n**作用**：前向时附加一个 dummy `NotImplemented` 节点（**保留输入的 `requires_grad` 属性**）；反向时该节点**抛出错误**。这有助于在大型模型中调试**精确定位 `requires_grad` 在前向传播中丢失的位置**。\n\n### In-place 或 View 算子的额外要求\n\n若算子**原地修改输入**或**返回与输入别名（alias）的张量**，需两步：\n\n**1. 除 `Autograd` kernel kernel 不同，autograd kernel 需要**回调 dispatcher** 才能到达 inference kernel（如 CPU/CUDA 实现）。\n\n### 4.1 编写 Dispatching Function（公共 C++ API）\n\n```cpp\nTensor myadd(const Tensor& self, const Tensor& other) {\n  static auto op = torch::Dispatcher::singleton()\n    .findSchemaOrThrow(\"myops::myadd\", \"\")\n    .typed<decltype(myadd)>();\n  return op.call(self, other);\n}\n```\n\n**逐行解释：**\n\n- **第一行**：从 dispatcher 查找与目标算子对应的 typed operator handle。\n  - `findSchemaOrThrow` 接收两个参数：算子的**命名空间限定名**（namespace-qualified name）和**重载名**（overload name，通常为空字符串）\n  - `typed` 将动态类型 handle 转换为**静态类型 handle**（会做运行时测试，确保给出的 C++ 类型正确），从而可以进行普通 C++ 调用\n  - 传入 `decltype(myadd)`，因为 dispatching function 的类型与注册到 dispatcher 的底层 kernel 类型相同\n  - **性能优化**：查找结果存于 `static` 变量，慢速查找只做一次；若算子名写错，首次调用时会报错\n- **第二行**：用传入 dispatching function 的所有参数 `call` 该 operator handle，实际触发 dispatcher，最终将控制权转移给适合本次调用的 kernel\n\n> 📌 PyTorch C++ API 中的**所有张量函数**在底层都是以同样方式调用 dispatcher 的。\n\n### 4.2 编写 Autograd Kernel（MyAddFunction 完整代码）\n\n```cpp\nclass MyAddFunction : public torch::autograd::Function<MyAddFunction> {\n public:\n  static Tensor forward(\n      AutogradContext *ctx, torch::Tensor self, torch::Tensor other) {\n    at::AutoNonVariableTypeMode g;\n    return myadd(self, other);\n  }\n\n  static tensor_list backward(AutogradContext *ctx, tensor_list grad_outputs) {\n    auto grad_output `myadd` 回调 dispatcher**\n\n**为什么必须这样做**：\n- **没有 (1)**：调用会**无限循环并栈溢出** —— 因为最高优先级 dispatch key 仍是 autograd，`myadd` 会再次把你送回本函数\n- **有 (1)**：autograd 被排除出待考虑的 dispatch key 集合，转到下一层 handler（即 CPU 或 版本运行。最低支持版本为 3.9。**建议在与最低目标 CPython 版本相同的环境中构建扩展**（本教程在 CPython 3.9 环境构建），构建出的单一 wheel 可在任意 CPython 3.9+ 环境运行。有三个关键配置点：\n\n**第一处：** 在 `extra_compile_args` 中指定 `Py_LIMITED_API`：\n```python\nextra_compile_args={\"cxx\": [\"-DPy_LIMITED_API=0x03090000\"]},\n```\n定义该标志可帮助验证扩展确实只使用了 [CPython Stable Limited API](https://docs.python.org/3/c-api/stable.html)，这是构建 CPython 无关 wheel 的必要条件。若不满足，构建出的 wheel 可能看似无关但在其他 CPython 环境中崩溃或产生静默错误。需避免使用不稳定 CPython API，例如 libtorch_python 的 API（尤其是 pytorch/python 绑定），只使用 libtorch 的 API（ATen 对象、算子和 dispatcher）。注意定义此标志并非完全保证，仍需自行测试验证。\n\n**第二、三处：** `py_limited_api` 参数与 `\"bdist_wheel\"` 选项：\n```python\nsetup(name=\"extension_cpp\",\n      ext_modules=[\n          cpp_extension.CppExtension(\n            ...,\n            py_limited_api=True)],  # Build 1 wheel across multiple Python versions\n      ...,\n      options={\"bdist_wheel\": {\"py_limited_api\": \"cp39\"}}  # 3.9 is minimum supported Python version\n)\n```\n需同时向 CppExtension/CUDAExtension 传 `py_limited_api=True`，并向 `\"bdist_wheel\"` 命令传入最低支持的 CPython 版本（此处为 3.9）。\n\n若扩展使用了 stable limited 集合之外的 CPython API，则**无法**构建 CPython 无关 wheel，应每个 CPython 版本各构建一个：\n```python\nfrom setuptools import setup, Extension\nfrom torch.utils import cpp_extension\n\nsetup(name=\"extension_cpp\",\n      ext_modules=[\n          cpp_extension.CppExtension(\n            \"extension_cpp\",\n            [\"muladd.cpp\"])],\n      cmdclass={'build_ext': cpp_extension.BuildExtension},\n)\n```\n\n### 2.3 LibTorch Stable ABI（PyTorch 无关性）\n\nWheel 兼容性的第二个轴：LibTorch agnosticism。CPython 无关性使单个 wheel 跨多个 Python 版本（3.9、3.10、3.11 等），LibTorch 无关性使单个 wheel 跨多个 PyTorch 版本（2.10、2.11、2.12 等），二者正交可组合。\n\n实现 LibTorch 无关性必须使用 ABI stable LibTorch API：例如不能用 `at::Tensor`，须用 `torch::stable::Tensor`。完整文档（迁移指南、支持的类型、栈式 API 约定）见 [LibTorch Stable ABI documentation](https://pytorch.org/docs/main/notes/libtorch_stable_abi.html)。\n\nStable ABI 的 setup.py 中 `TORCH_TARGET_VERSION=0x020a000000000000` 表示目标 LibTorch Stable ABI 的最低 PyTorch 版本为 2.10。版本格式为：`[MAJ 1 byte][MIN 1 byte][PATCH 1 byte][ABI TAG 5 bytes]`，故 2.10.0 = `0x020a000000000000`。\n\n若 stable API/ABI 不含所需内容，可使用非 ABI-stable LibTorch API，但需为每个 PyTorch 版本分别构建 wheel。\n\n---\n\n## 3. 定义算子与注册后端实现\n\n### 3.1 CPU 实现\n\n**ABI-Stable LibTorch 定义算子：TORCH_LIBRARY 用法与 Schema 定义\n\n定义算子的步骤：\n1. 为算子选择命名空间，推荐使用顶层项目名；本教程使用 `\"extension_cpp\"`\n2. 提供一个 schema 字符串，指定算子的输入/输出类型以及输入 Tensor 是否会被 mutate（变更）。除 Tensor 和 float 外还支持更多类型，详见 [The Custom Operators Manual](https://pytorch.org/docs/main/notes/custom_operators.md)。若编写会 mutate 输入 Tensor 的算子，参见“Creating mutable operators”一节。\n\n**ABI-Stable LibTorch API：**\n```cpp\nSTABLE_TORCH_LIBRARY(extension_cpp, m) {\n  // Note that \"float\" in the schema corresponds to the C++ double type\n  // and the Python float type.\n  m.def(\"mymuladd(Tensor a, FakeTensor kernel 指定如何由输入元数据计算输出元数据，应返回具有正确 Tensor 元数据的 dummy Tensor。\n\n推荐从 Python 通过 `torch.library.register_fake` API 完成（C++ 亦可，详见 [The Custom Operators Manual](https://pytorch.org/docs/main/notes/custom_operators.html)）：\n```python\n# Important: the C++ custom operator definitions should be loaded first\n# before calling ``torch.library`` APIs that add registrations for the\n# C++ custom operator(s). The following import loads our\n# C++ custom operator definitions.\n# Note that if you are striving for Python agnosticism, you should use\n# the ``load_library(...)`` API call instead. See the next section for\n# more details.\nfrom . import _C\n\n@torch.library.register_fake(\"extension_cpp::mymuladd\")\ndef _(a, b, c):\n    torch._check(a.shape == b.shape)\n    torch._check(a.dtype == torch.float)\n    torch._check(b.dtype == torch.float)\n    torch._check(a.device == b.device)\n    return torch.empty_like(a)\n```\n\n---\n\n## 5. 混合 Python/C++ 注册：三种加载方式\n\n本教程在 C++ 中定义算子、添加 CPU/CUDA 实现，在 Python 中添加 FakeTensor kernel 和 backward 公式。**这些注册的加载（导入）顺序很重要**（顺序错误会报错）：必须先加载持有算子定义的 C++ 库，再调用 `torch.library` 注册 API。共有三种方式：\n\n**方式一（PYBIND11_MODULE，不可用于 CPython 无关 wheel）：** 定义 `_C` 的 dummy Python 模块，`import _C` 时会加载扩展的 `.so` 文件并运行 `TORCH_LIBRARY` 和 `TORCH_LIBRARY_IMPL` 静态初始化器。但 `pybind11` 不保证只用 stable limited CPython API，因此**无法用 `Py_LIMITED_API` 编译**，即无法构建 CPython 无关 wheel：\n\n```cpp\n// in, say, not_agnostic/csrc/extension_BAD.cpp\n#include <pybind11/pybind11.h>\n\nPYBIND11_MODULE(\"_C\", m) {}\n```\n```python\n# in, say, extension/__init__.py\nfrom . import _C\n```\n\n**方式二（stable API 版 dummy 模块）：** 用稳定 API 调用替换不稳定的 `PYBIND11` 调用。以下代码可用 `-DPy_LIMITED_API=0x03090000` 编译，成功创建可从 Python 导入的 `_C` dummy 模块（详见 [extension_cpp/__init__.py](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/__init__.py) 与 [extension_cpp/csrc/muladd.cpp](https://github.com/pytorch/extension-cpp/blob/38ec45e/extension_cpp/csrc/muladd.cpp)）：\n```cpp\n#include <Python.h>\n\nextern \"C\" {\n  /* Creates a dummy empty _C module that can be imported from Python.\n    The import from Python will load the .so consisting of this file\n    in this extension, so that the TORCH_LIBRARY static initializers\n    below are run. */\n  PyObject* PyInit__C(void)\n  {\n      static struct PyModuleDef module_def = {\n          PyModuleDef_HEAD_INIT,\n          \"_C\",   /* name of module */\n          NULL,   /* module documentation, may be NULL */\n          -1,     /* size of per-interpreter state of the module,\n                    or -1 if the module keeps state in global variables. */\n          NULL,   /* methods */\n      };\n      return PyModule_Create(&module_def);\n  }\n}\n```\n```python\nfrom . import _C\n```\n\n**方式三（torch.ops.load_library，完全避免 Python.h）：** 用 `torch.ops.load_library(\"/path/to/library.so\")` 加载扩展编译出的 `.so` 文件。此方式不会创建 `_C` Python 模块，因此不能 `import _C`；不再依赖 import 语句触发注册，而是由 `torch.ops.load_library` 完成。难点在于定位 `.so` 文件位置（并非总是容易）：\n```python\nimport torch\nfrom pathlib import Path\n\nso_files = list(Path(__file__).parent.glob(\"_C*.so\"))\nassert (\n    len(so_files) == 1\n), f\"Expected one _C*.so file, found {len(so_files)}\"\ntorch.ops.load_library(so_files[0])\n\nfrom . import ops\n```\n\n---\n\n## 6. 训练支持：autograd 注册\n\n> ⚠️ **关于用户提到的 `torch::autograd::Function` /
