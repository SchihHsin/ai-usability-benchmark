# 新实验的评价与证据规则

当前版本：`v2-coverage-2026-09-15`。M2目标五档及均值、M8调用成本五档、M3/M10五档已确认，具体见[已确认指标规则](confirmed-metrics.md)。其他指标继续记录观测，M11不计算。此前`v2-draft`全部分值仍为null；旧规则2026-09-14是独立兼容版本。

## 任务问题对

以共同开发意图、起始状态、要求的产出及需求ID配对。生态术语可以不同；不得一侧只要概念解释，另一侧要求完整实现。按实际任务包保留两个完整问句、生态差异、需求与适用性。已有题目不因更新Skill自动改写；若修改任务范围，形成新任务包版本，不能与旧问题直接混算。无法对应的单侧任务可保留分析，但排除配对统计。未确定的硬件、框架、数据或实现路线不能自行补成“相同难度”。

## 指标观测

| 指标 | 本指标的评价范围与记录 | 容易混淆的问题及其归属 |
|---|---|---|
| M1 | 首次相关官方命中的查询、工具列表位置、此前搜索和改词；后续补充搜索另计，不能降低已经发生的首次发现表现 | 正文实际取得状态属于M2；搜索调用成本属于M8。 |
| M2 | 对实际选择读取的官方资源逐次记录目标正文完整/部分/未取得/未知及依据；保留范围、障碍和恢复。静态/SSR只是有证据时填写的交付属性，不作为新实验高低分的直接依据 | 官方内容充分性属于M3；版本配套属于M4；获取调用成本属于M8。 |
| M3 | 逐需求检查实际取得的官方内容支持了什么、缺什么；区分未取得与取得后信息不足，不把未读到的网页判为写得差 | 正文获取状态属于M2；版本选择与组件配套属于M4；最终操作方案属于M10。 |
| M4 | 资料是否提供可选择的版本或支持范围，以及组件配套依据；版本多不自动低分，有明确推荐不等于没有其他版本 | 正文获取状态属于M2；一般操作内容充分性属于M3；最终回答的版本说明属于M9。 |
| M5 | 分别统计非官方候选、实际读取、独立来源及能补充任务信息的来源；去重规则和来源清单可追溯 | 第三方内容支撑与质量属于M6；检索和读取成本属于M8。 |
| M6 | 已读取第三方内容的依据、适用性、一致/冲突、独立案例与补充作用；官方博客按发布者归属官方，镜像不重复算独立经验；未知日期不猜测 | 第三方来源数量属于M5；版本选择与配套属于M4；最终操作方案属于M10。 |
| M7 | 协议指定时点的模型自评及简短依据，单独保存；不是训练覆盖率或客观正确率 | 来源的实际内容支撑属于M3/M6；最终回答的版本说明和操作方案分别属于M9/M10。 |
| M8 | 实际搜索/获取派发数、批量query数、返回状态、重试、可观察的时间/token/费用及缺失状态；语义性获取失败另判。旧0.5/4系数是设计权重，不是测得的真实耗时 | 官方正文获取状态属于M2；官方与第三方内容支撑分别属于M3/M6；最终操作方案属于M10。 |
| M9 | 最终回答是否说明任务所需的版本或适用范围与配套关系；概念任务无需版本时标N/A | 来源中的版本说明属于M4；最终操作步骤及代码问题属于M10。 |
| M10 | 最终回答对任务要求的实质完整性、接口/参数/代码的一致性；合理的用户参数占位不直接扣分。未运行不能称已验证成功；概念任务不强求可执行代码 | 官方与第三方内容支撑分别属于M3/M6；最终回答的版本说明属于M9；获取成本属于M8。 |
| M11 | 草案阶段不计算；更改基础指标后不能沿用旧综合公式并称其有效 | 各项问题保留在对应基础指标中；本项不另作内容判定或重复扣分。 |

若获取工具明确说“网页未提供，下面另行补充”，将补充片段标为tool_generated_supplement，原网页提取片段与补充片段分别引用。补充说明不能用来提高原网页的内容支撑评价（M3/M6）；它仍属于Agent实际可见输入，最终回答按M10另行检查。无法区分时标unknown，不因返回长、含代码就推定均来自网页。

同一段原文可以被多个指标引用，但各指标须说明自身范围内的可观察事实。不能因另一指标低分而连带扣分；也不能把同一个“版本配套未说明”同时作为M3和M4的扣分理由。

来源内容、工具实际返回、最终回答分别评价。支持充分、内容真实正确和代码运行成功是不同判断，有多少验证就报告多少。所有内容判断带原文证据；自动计数与评价者推断分开。

## 问题与恢复

每个问题保存：受影响需求、遇阻事件与证据、替代来源及尝试顺序、恢复状态（完整/部分/未恢复/未知）、最终仍缺的内容。两模型同样遇到导航框架但其中一个后来取得官方正文，可以同时报告共同障碍和恢复差异。

共同问题由相似的可观察现象及其证据支持，不要求同一分数。没有访问相关资料的运行标“未观察”，不能当“无问题”。工具故障、权限限制、页面获取现象与网站内部原因区分；未核实技术原因时不将其写成确定机制。

跨模型比较先在每个模型内比较两生态，再比较同一任务上的共同问题、恢复路径及剩余缺口。保留反例、观察范围和分母。发现一致支持所测条件下的稳定性，不单独证明整个评分体系有效。
