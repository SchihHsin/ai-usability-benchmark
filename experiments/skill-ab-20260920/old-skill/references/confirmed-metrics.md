# 已确认的M2、M3、M8、M10规则

版本：`v2-coverage-2026-09-15`。本版确定以下四项；M1/M4/M5/M6/M7/M9继续保存观测，M11暂不计算。不是整套评分体系已经完成验证。旧版`v2-draft`仍保持全部分值为null，不追溯修改既有运行。

## M2：官方目标正文获取状态

以实际选择读取的独立官方文档为平均单位，文档各评一次，再等权平均。执行前固定任务需求及文档纳入/去重规则；执行中通过实际请求形成文档清单，不预先把“解释错误”“给出步骤”等信息需求各当一篇文档。所有尝试读取的官方文档均纳入，包括仅框架和失败项，不只挑成功项。

同一篇文档的失败重试、分页、分段读取合并为一个document ID，依据本轮累计取得的正文判断最终状态；已经取得的正文不会因后一次失败而消失。同一文档满足多个任务需求也只计一次，多个requirement_refs不增加权重。官方不同格式且确认为相同正文时合并；不同版本或不同文档不因标题相似自动合并，保存identity_basis和对应URL。第三方镜像在来源与恢复记录中关联原文，不提高官方M2。

例如A读了3次后完整取得，B读了1次仍只有框架：A=5、B=2，均值(5+2)/2=3.5，四舍五入得到4档；分母是2篇文档，不是4次获取。4次调用计入M8；A首次遇阻的证据保留。

| 分值 | 判定 |
|---|---|
| 1 | 未取得页面内容；有实际访问失败证据 |
| 2 | 取得页面框架，但没有正文 |
| 3 | 已取得部分正文，可核对的正文单元覆盖率大于0且小于50% |
| 4 | 正文单元覆盖率至少50%但不足100%，或全部单元均有返回但仍有明确单元内截断 |
| 5 | 有证据确认全部目标正文完整取得 |

覆盖率 p = 本轮官方返回中可定位的正文单元数 / 参照正文单元总数。50%是本研究固定设计阈值，并非文献验证的自然分界。

执行前在protocol.m2_coverage_unit固定paragraph/section/page之一及拆分规则（m2_unit_rule）；同一批运行统一，不按取得结果选择分母。正文单元须有唯一ID，保留reference_units、returned_units及参照证据。单位等权衡量的是结构覆盖，不是字数比例或知识价值。部分单元只计一次；单元内截断单独记录，不能因所有章节标题出现便算正文覆盖。仅标题不算正文单元取得。

参照正文限同一版本、同一范围；独立核对得到的参照只用于事后评价，不加入Agent执行上下文、不算本轮获取成功或M8调用。该核对的来源、时间、工具、内容/快照及范围须保存在evaluation.json的coverage.reference对象内。参照证据和本轮实际取得证据分别保存。

摘要、摘录、截断、HTML/Markdown均为独立属性，不再直接映射3/4分。摘要无法逐单元可靠映射时，标unknown、score=null；不能按主题提及或字数猜覆盖率。无法确认分母时，已知“部分正文取得”也保留null，不删除该文档后平均。1/2分与有独立完整性依据的5分不强制计算覆盖率。

M2不评价正文是否包含操作说明（M3）、版本配套（M4），或最终方案（M10）。原文只有一句且完整取得也可5分。第三方镜像补足不提高官方M2。重试补齐可5分，但首次障碍仍保存；未尝试、权限未配置、日志缺失不算1分。不能仅凭HTTP 200、返回很长或没有截断提示认定完整。

任务级等权平均：

\[
\bar{x}_{M2}=\frac{1}{n}\sum_{i=1}^{n}s_i,\qquad M2=\lfloor\bar{x}_{M2}+0.5\rfloor.
\]

例如五个不同目标为2、3、4、5、5，均值3.8，四舍五入为4分。保留原始均值、每项目标分、分数和与目标数；4.5进为5，不使用银行家舍入。任务级4分是平均档位，不表示所有目标均为“不完整正文”。

同时报告未取得正文数（1/2分）、未完整取得数（3/4分）与未知数；保留目标的具体return_kind，以区分摘要和截断。只要纳入文档仍有未知，均值与总档位保持null，不删除未知项后平均。同一目标从摘要/截断进一步补齐为完整正文时，最终记5，原有障碍另存。

## M3：已取得官方内容对任务要求的支撑

M3评价已取得官方正文的内容充分性；正文获取状态属于M2，版本选择与组件配套属于M4，不作为M3的评分依据。

执行前冻结任务需求ID、说明和importance（core=完成任务必需；supplementary=题目要求的辅助说明），明确其中属于M3的步骤、解释、参数、实现或诊断内容要求。下表的“核心环节”“辅助说明”“全部要求”均限于上述内容范围。不能在看到结果后增加辅助要求或改变重要程度。

| 分值 | 判定 |
|---|---|
| 1 | 已取得相关正文，但没有提供可用于完成任务的信息 |
| 2 | 有背景、术语或方向说明，尚不足以完成任何核心环节 |
| 3 | 能支撑部分核心环节，仍缺影响完成任务的关键内容 |
| 4 | 所有核心环节有充分支撑，题目要求的部分辅助说明仍缺失 |
| 5 | 纳入M3的全部预定内容要求均有充分支撑，未发现这些内容自身存在影响任务使用的未解决矛盾 |

先逐需求保存实际支持及缺口，再给总档。只有背景方向是2；已有具体可用操作/解释、但核心任务仍不完整是3。内容自身矛盾指步骤、参数解释或实现说明前后不一致。

相关正文全部未取得时标`not_assessable`，score=null，不给1。混合情况分别说明“正文受阻”与“取得后仍缺信息”；总档仅指实际取得内容的支撑，不是整个官网原文质量。检查范围或核心/辅助划分不足以支持确定档位时保持pending，不猜分。

如果纳入M3的预定内容要求全部是核心要求，则没有4分所对应的辅助缺口，允许跳过该档；不得为了用满五档临时增加任务要求。

## M8：搜索与获取调用成本

保存成本明细`(S,F,R,U)`：S=实际搜索调用数；F=实际获取调用数（包括失败）；R=同一获取目标的重试调用数；U=未取得目标正文的获取调用数。R是S/F调用中的子集，U是F的子集，R/U分别报告，不重复加到S/F上。部分正文取得不计入“完全未取得”的U，另留M2状态。

S/F从实际派发事件计算；R/U先根据目标和真实返回判定、列出请求ID，再由程序计数。是否为同一目标的重试不能仅凭相邻调用或同一URL推断。不能判断R/U时为null，不能填0。未派发就被预算/权限阻止的请求不计入S/F/U。日志不完整时同时报告缺口。

时间、token和费用在工具实际暴露时另列；并发耗时之和不是用户等待时间。本版总调用成本为`C=S+F`，不沿用旧版`S+0.5F+4U`。

| M8分值 | C实际调用数 |
|---|---|
| 5 | 1–2 |
| 4 | 3–4 |
| 3 | 5–6 |
| 2 | 7–8 |
| 1 | ≥9 |

C=0不自动给5分，保持待定或不适用。这是每两次调用一档的统一设计约定，不是实测时间等价；所有任务和模型共用阈值，不按本次分布调整。失败和重试按实际调用计一次。比较成本时同时看任务需求支撑和答案完成程度。

## M10：最终操作方案的完整性与一致性

M10评价最终回答的操作步骤与代码；来源内容支撑属于M3/M6，最终回答的版本说明属于M9。不能只因版本未交代清楚或来源得分低而降低M10；须指出操作方案本身的具体缺口。

| 分值 | 判定 |
|---|---|
| 1 | 没有形成与任务相关的操作方案 |
| 2 | 只有方向或流程概述，缺少具体操作 |
| 3 | 有具体步骤，但核心链路缺失或接错，需要补充实现、接口或构建环节 |
| 4 | 核心链路已形成，但存在可明确定位、局部修正的实质错误或遗漏 |
| 5 | 在声明的适用条件下，必要步骤完整、前后一致，内容检查未发现实质缺口 |

3与4按修正范围区分：需要重新补齐/选择核心实现或接口，属于3的边界；路线已经完整、仅需明确局部修改，属于4的边界。最终分数应检查整个主方案，不能用某一处错误直接代表整份答案。

合理替换安装路径、硬件型号等环境参数不自动扣分。5分不是实机运行成功；runtime_validation单列not_executed/executed，已执行时保留结果证据。概念解释任务不强求代码，对无操作要求的任务标not_applicable。

按题目要求评主方案。额外方案中的错误单独记录，先说明是否影响主方案或题目要求；不因模型多写内容自动奖励/惩罚。4/5需要说明适用条件；没有足够材料完成全方案核对时保持pending。

## 评价输入与校验

运行metadata选择本版本。需求清单置于`metadata.protocol.requirements`，每项有id、description、importance。用`run_log.py template --run-dir ...`输出评价模板到标准输出；编辑后用evaluate写进原evaluation.json，不增加默认交付文件。

M3/M10的非空score必须为整数1—5，status=scored，并有reason、requirement_refs及可解析的原文evidence_refs。M3还须有official_body_observed=true，冻结需求含core/supplementary分类。逐项requirements判定必须完整并含reason和证据引用；完整整理任务需求不等于把所有需求都用于每个指标评分，M3的requirement_refs及判定理由限于其内容范围。M10须声明scope=main_solution、适用条件和runtime_validation；有额外方案时另列。

M2 observation.targets保存去重后的文档清单：target_id作为document ID，另含description、requirement_refs、urls、identity_basis、score、initial_state、final_official_state、reason、evidence_refs、event_refs、return_kind、state_basis。相同文档的全部获取返回都列入event_refs，保留初次障碍；score基于实际官方fetch返回原文。用`scripts.document_metrics.aggregate(targets)`计算aggregate，band填任务score。

observation.fetch_inventory逐个覆盖实际fetch请求：request_id、source_class（official/third_party/unverified/not_dispatched）、document_id、reason、event_refs。official映射到文档ID；其他类别document_id为null。未派发请求不计入官方M2或M8；第三方镜像单列来源与恢复关系。归属未核实或清单不完整时任务M2保持null，不能删除不利项后算平均。程序校验清单覆盖和去重，文档身份仍须有实际依据，不能声称脚本自动证明两页相同。

M8 observation保留C对象中的S/F/R/U（兼容原字段名），total_calls存S+F；retry_request_ids/no_body_fetch_request_ids未知时用null。程序核对派发事件、总数与分档；运行未结束、存在未返回调用或因超时/客户端错误中断时，只保存已观测成本，score保持null；score可待定，正式填分须status=scored和reason。M2/M8也按此状态要求填分。

其他指标和overall仍为null。本版M2不按恢复路径分档，M8继续按实际调用数评价成本。此前v2-partial版的无分值规则见[旧版定义](confirmed-metrics-partial-2026-09-14.md)，校验继续兼容，既有实验不自动重算。

脚本验证格式、数值、版本和引用，不会自动读懂网页或证明评价者选择的档位正确。内容判断需按上述边界逐项核验，分歧保留原文与修订理由，不按模型标签调整分数。

此前将4分定义为经替代路径取得的版本保留于[旧版路径分档](confirmed-metrics-path-2026-09-14.md)，版本号为v2-five-band-2026-09-14。旧实验不会自动重算或替换版本，新旧M2不得混算。

上一版固定正文目标的规则见[2026-09-14正文状态版](confirmed-metrics-body-state-2026-09-14.md)，旧数据保留原协议与分值；该历史版本保留旧定义；当前覆盖版修改3/4分判据，均值公式和指标职责保持不变。

## 本版变更与证据字段

旧文档状态版见[上一版](confirmed-metrics-document-2026-09-15.md)。新旧M2的3/4分含义不同，不混算、不自动修改旧实验。M3/M8/M10分档保持不变。

M2每篇文档增加acquisition_level：page_not_obtained/frame_only/partial_body/complete_body/unknown；return_kind独立记录实际返回形式。coverage（3/4分必填）包含unit_type、reference_units、returned_units、within_unit_truncation（布尔值）和reference。reference含url、version_scope、captured_at、tool、content、unit_spans（单元ID映射到content的[start,end]字符位置）。每个returned_unit须在unit_evidence中关联该文档本轮官方fetch原文evidence_refs。5分另保存completeness_basis。脚本只能检查结构、数值与引用，单元划分和原文对应仍需人工/评价者核对。

M8各模型使用同一工具条件和调用上限，同时展示S、F、C及五档；不把8/9次跨档解释为成本突变。具体成本阈值不是实测耗时。文献及各指标对应范围见[literature-and-measurement.md](literature-and-measurement.md)。
