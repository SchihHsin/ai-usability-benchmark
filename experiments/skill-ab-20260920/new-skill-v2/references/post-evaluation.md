# 后评清单

从同一运行process.jsonl生成评价修订，引用必须与真实事件ID、原文片段对应，不能用模型自己编的编号。结果存evaluation.json，不替换原始记录。

| 项 | 必须完成的工作 |
|---|---|
| M1 | 逐查询检查完整结果列表，人工核对最早相关官方命中及其位置；错误查询与未知分开 |
| M2 | 建立全部官方获取文档清单、合并同文档重试；逐文档判断返回形态与完整性；未知不得删掉后平均 |
| M3 | 将已取得官方正文与执行前任务要求逐项对照；记录缺口位置，不用来源页标题代替正文 |
| M4 | 从官方返回列出版本选择条件、冲突或缺失；多版本本身不扣分 |
| M5 | 核对全部查询的第三方结果，确认发布主体与相关性，去除同文转载，保留计数依据 |
| M6 | 从第三方材料提取会改变操作/结论的关键陈述，核对支持、反驳或未知；没有核对不等于已经证明错误 |
| M7 | 逐条核对检索前完整答案；允许使用随后取得的证据做后评，但不能把补充后的答案当先验 |
| M8 | 从实际派发事件计算S/F，失败一次只计一次；拒绝派发不计 |
| M9/M10 | 直接引用最终答案，版本与操作分别评价，实际运行状态另记 |
| M11 | 输入M1—M8有据且适用时按百分制公式计算；未知状态分别列出 |

状态：scored（已评分）、not_assessed（尚未评价）、insufficient_evidence（评价过但证据不足）、not_applicable（不适用）、blocked（有证据的渠道受阻）。not_assessed不能写成insufficient_evidence。渠道受阻的综合处理须单独核对，不把受阻的M3改造为1分；本计算器对缺项暂拒绝产出点值，防止静默补0。

不强制新增模型运行才能后评；优先复用现有原始返回。需要独立全文参照时单独标明它是事后核查，不计入Agent本轮获取成功。没有完整核验就报告具体未完成工作，不声称新版已全面验证。
