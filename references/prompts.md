# 配置与可复制Prompt

## 准备协议

先选择真实模型与工具。Skill不负责切换模型、购买服务或注入API密钥。多模型使用同一工具配置；如果只能用不同平台工具，保存差异并据此界定研究结论。

协议至少规定：

| 内容 | 需要确定的值 |
|---|---|
| 身份 | protocol_version、rubric_version、任务包/脚本哈希 |
| 模型 | 实际版本或别名、取得依据、可锁定情况 |
| 工具 | 搜索提供方/工具、URL读取实现、语言/区域、返回条数、截断限制 |
| 运行 | 上下文/记忆、公共指令、采样/推理参数、预算、超时/重试、停止条件 |
| 判定 | 来源去重、版本统计对象、失败获取的定义、M7采集时点、统一reference_month |
| 顺序 | 任务ID、生态、模型、轮次、run_id和进度清单 |

已由用户或项目确定的值直接使用，不重复确认。没有规定的普通实施细节可给出明确默认并写入配置；关键缺失信息列明，不声称已控制不存在的能力。不新增强制校准或试跑批次。

实际操作时将下列方括号替换成真实任务清单的值。路径由用户项目决定，不能照抄其他人的本地地址。API客户端能配置同一Skill时完整安装本目录；只能读文件时显式指向SKILL.md。

## 1. 检查环境

```text
请使用 ai-usability-benchmark Skill，读取项目的protocol.json。
先检查实际可用的搜索、URL内容获取、文件保存和Python能力，不执行开发任务。
列出真实工具名、模型配置/版本能否读取、是否能保存真实工具返回。
核对协议中的工具预算、停止条件、返回条数和截断设置。
已确定的配置直接沿用。缺失或不支持的内容如实说明，不模拟工具调用。
不读取其他模型结果或旧论文结论。
```

## 2. 执行一个任务

```text
使用 ai-usability-benchmark Skill。
协议路径：[协议文件]
任务包路径：[任务文件]
任务ID：[任务ID]
生态：[生态]
实际模型配置标签：[标签]
轮次：[轮次]
运行目录：[全新运行目录]

只执行这一任务的一侧生态，用任务包中的完整问句与相同工具协议。
模型标签只是记录；模型身份以客户端实际配置/响应为准，不可见处注明。
本轮用途：[验证材料/采用已定稿协议的正式实验]。
新运行采用v2-five-band-2026-09-14；任务要求、核心/辅助分类与acquisition_targets（id、description、requirement_refs）在执行前确定；不同模型及生态固定同一目标范围。
既有v2-draft记录保持原样，不自行增加额外实验。

读取Skill引用的recording、evaluation、confirmed-metrics；旧版评分仅在协议显式指定时读取rubric。
按协议固定时点保存M7自评及简短依据。
真实搜索和读取资料，回答任务问题。
由客户端记录实际请求、派发状态与完整返回，保存全部搜索结果及顺序。
若客户端未接入或无法导出，列明日志缺口，不靠模型回忆重建过程。
保留查询改写、URL来源、失败/重试、替代入口和停止原因。
分别记录资源格式、获取方式、工具返回形式、交付证据和正文取得状态。
工具未暴露的字段标为未知，不补造；摘要和分析不覆盖原始返回。
问句、配置、工具过程、M7原始自评与最终回答保存到process.jsonl。
执行时正常解决任务，不自行重建调用计数、手填RAW或编造证据ID。
后处理将需求覆盖、问题及恢复路径、指标观测写入evaluation.json。
只交付这两个运行文件；执行模型不自报正式分数，后处理按版本评价。

不读取另一侧、其他模型或旧实验结果，不要求生态得分或模型结果趋同。
不修改计分规则，不自动修改论文或公开上传材料。
最后给出运行目录、完成状态、停止原因和缺失项。
```

新会话、实际模型选择及工具一致性由客户端/调度器保证；仅把“独立上下文”写进Prompt不能自动创建独立环境。不支持自动批量独立会话的客户端就逐任务新开，不在一个累积上下文中冒充独立运行。

## 3. 整理计分

```text
按 ai-usability-benchmark 的evaluation与recording规则整理指定运行目录。
不新做检索，不把缺失的返回内容靠回忆补齐。
检查已登记调用和返回，计数来自事件；每个内容字段保存依据。
真实无第三方来源与没有检查/没有日志分开。
不按模型标签调整评分，争议字段按证据复核，保留前后判定和理由。
在evaluation.json中保存观测、需求覆盖、问题、恢复状态及证据引用，绑定process哈希。
引文来自真实事件及精确字符区间，检查引用是否存在且足以支持判断。
先遇阻后恢复，两者都保留；未观察与无问题区分。
v2-five-band-2026-09-14：M2按预定目标评分、保留初次及最终官方获取状态，等权平均并四舍五入，另报未取得/部分取得/未知数；M8按S+F五档评分并报告S/F/R/U；M3/M10按confirmed-metrics五档及证据评价。
M3核心/辅助分类未预先确定、证据不足或不适用时不硬填分。其余指标及综合分保持null。
v2-draft旧记录的分值仍保持null，不调用旧score_template.py。
仅显式选择旧规则2026-09-14时按其输入格式及参照月计分，结果归入对应评价修订。
用run_log.py evaluate写入修订，再用check检查；旧版计分的临时导出不是额外交付物。
```

## 4. 下游分析交接

```text
基于已核验的process.jsonl及evaluation.json分析；按版本展示获取状态、成本和已确认分项评分；不得混算新旧版本或使用未确定分值。
按“场景分布→具体缺口→来源互补”组织，先在各模型内比较两个生态，
再比较模型间的差异方向、幅度和具体证据，保留反例与缺失分母。
展示单模型生态矩阵、跨模型生态差值和单任务详情，均能下钻到证据。
多个模型结论一致仅说明所测条件下的一致性，不单独证明全部指标有效。
先交付分析与图表，不在未得到论文修改指令时改稿或提交。
```

下游分析、统计和矩阵实现独立于执行Skill。本仓库提供运行/计分数据接口及建议视图，不包含自动运行三个模型、生成交互矩阵或提交论文的程序。
