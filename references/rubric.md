# 兼容说明

本文件是旧版`2026-09-14`评分规则。仅用于显式选择此版本的运行；新实验默认观测规则见[evaluation.md](evaluation.md)，不得把其中的新定义直接套入本公式。

# 字段判定与统一计分

规则版本：`2026-09-14`。先按证据提取观测，再让同一份脚本计算。观察值不同可以得分不同；不以模型之间的分差决定修改字段。

## 字段与依据

| RAW字段 | 取值及共同判定 |
|---|---|
| `rounds` | 实际搜索工具调用次数，非负整数。一次调用含多查询时额外保存query_count，不临时把查询数改称轮数。协议需明确批量调用能力是否一致 |
| `rank` | 首次命中官方资料的有序列表位置，正整数。保存query/event ID及rank_basis；只有工具列表位置时不声称真实SERP排名。未命中/未暴露用null并注明，不用0或999代替 |
| `refine` | 为找到官方源是否需要改写查询；找到后继续扩展搜索不自动算改写失败。true/false，未知null |
| `fetch` | 全部实际内容获取调用数，含失败与重试。其他类型调用分别保存，不混入 |
| `fetch_fail` | 获取调用未返回目标正文的次数：如仅导航、阻断页、空返回/错误。完整正文但缺诊断细节不算获取失败。部分取得是否失败取决于该次请求目标，按同一规则标注；保留各次事件以便核对 |
| `core_fetch` | `static/ssr/partial/spa/robots`；见下文M2。未知技术分类用null，不因HTTP200、URL后缀或工具转换成MD猜类别 |
| `body_status` | 可选独立观测：`retrieved/partial/not_retrieved`。获取状态有证据、技术分类未知时，M3仍可据正文评分；M2暂缺 |
| `exec` | 实际取得的官方正文是否包含可操作的核心步骤/命令/代码；不等于已上机运行。概念任务不凭空填true |
| `ref_level` | `exhaustive`：覆盖任务预定核心需求及相关参考细节；`core_only`：主流程有依据但参考不全；`overview`：方向/概念概述；`fragment`：零散信息；`none`：取得内容中没有相关说明。逐项列需求与证据，禁止按篇幅猜 |
| `n_versions` | 已取得资料中、与当前选择相关的备选版本数。先保存component→versions→适用关系，再按任务确定统计对象；不同组件正常配套版本不直接相加。缺少版本信息用null，不用0伪装版本明确 |
| `ver_matrix` | 实际取得的官方配套矩阵能否支撑当前版本选择；只有链接不算取得 |
| `ver_irrelev` | 当前任务是否不依赖具体版本，由任务需求判断，两侧使用一致要求；不能因没找到版本信息就填true |
| `two_axis` | 是否需要选择两类配套要素且取得了可锁定依据；保存具体两轴及关系 |
| `sources` | 去重非官方来源的SOURCE_CRED类型列表；确实检查后没有第三方来源为[]，尚未检查/记录丢失为null。保存每个source_id及归类理由 |
| `platforms` | 与sources逐项对应的域名token；统一域名规范，保留原URL。未知域名时整字段null，不把未知写成重复的字符串占位 |
| `dates` | 与sources逐项对应的`YYYY-MM`或null。页面发布日期/更新时间/搜索显示日期分别保存并说明采用哪种；缺日期不编造 |
| `consist` | `high`：多来源有具体一致的操作/版本证据；`mid`：深度参差或不能充分互证；`low`：存在具体冲突。单一来源不因为没有反例就判high |
| `own` | 1–5模型自评，按下表，固定采集时点并保存简短理由；不可客观核验为训练覆盖密度 |
| `churn` | `stable/moderate/fast`，任务所涉知识迭代节奏，有依据并在任务协议中固定；不是已测得的模型知识截止日期 |
| `pin` | `exact`：最终指导给出所需确切适用版本；`mostly`：主要版本明确仍有少量空缺；`range`：只确定范围；`none`：未锁定。以最终回答为依据 |
| `repro` | `copyrun`：指导包含所需步骤、命令/代码及前提；`params`：主要步骤有，需补环境参数；`partial`：需补实质步骤；`skeleton`：仅框架。标签不是实际运行结果；独立保存是否执行过运行验证 |

布尔字段必须是真正的JSON布尔值，不能把字符串`"false"`当false。计数不能为负。来源列表需要保留去重前候选以及去重依据，不删除原始搜索结果。

### M7自评锚点

| own | 自评描述 |
|---|---|
| 1 | 无法依靠自带知识形成相关解题框架 |
| 2 | 仅能给出零散概念或一般方向 |
| 3 | 能形成主要解题框架，关键命令/参数需要外部资料 |
| 4 | 能提出较完整指导，但需核对版本或少量关键细节 |
| 5 | 自认为可给出具体且适用的完整指导；仍只是自评，需外部证据检查 |

这些锚点用于统一自评语言，不让不同模型假装具有相同先验能力。建议检索前单独采集，保存为self-assessment证据；如果采用其他时点，应全批统一并记录。

### M2口径：沿用已确认映射

- `robots=1`：有访问限制的实际依据。
- `spa=2`：相应页面的当前获取方式仅返回框架/导航，目标正文未取得；保存所见结果，不声称所有浏览工具都会失败。
- `partial=3`：部分目标正文取得，仍有目标正文因技术获取障碍未返回。
- `ssr=4`、`static=5`：分别有相应交付方式的依据，且目标正文可取得。

“取得正文但内容太泛”归M3；使用镜像、多个读取步骤或返回Markdown不自动导致M2升降。静态/SSR不能仅凭读取成功推断。技术类别无法判断就保留null及依据缺口；body_status可单独描述正文状态。

原始页面格式、工具读取方式、工具返回表示和正文取得状态均在日志中独立保存。

## 来源归属与去重

发布者身份决定官方/第三方，托管平台不决定归属。厂商发布的文档、博客、代码仓和官方论坛进入官方渠道；独立作者、非目标厂商的云技术文章等根据实际发布者归类。厂商资料的简单转载不当作独立社区经验，保存转载关系。

SOURCE_CRED保留历史键以支持旧调用，但正式JSON输入禁止`official_doc/official_repo/official_forum`混入sources。其余类型：cloud_vendor=4、arxiv=4、qa_reputation=3.5、tech_blog=3、aggregator=2.5。实际可信度仍是规则估计，不等于内容已被证明正确。

sources按所取得候选材料的稳定标识去重；不同URL是否是同文须有依据，不粗暴删除全部查询参数。原始结果列表、每次访问和页面版本完整保留。

## 公式和分档（与脚本对应）

- M1：搜索次数≥2且refine=true为2，次数≥2为3；其他情况rank=1为5，rank≤6为4，rank≤10为3，其余为2。脚本有排名缺失时保留待定，不拿后续搜索次数猜已命中。
- M2：见上表。
- M3：正文未取得显示“受阻”；exhaustive且exec为真/假→5/4，core_only→4/3，overview→3，fragment→2，none→1。
- M4：版本无关或备选数≤1→5，有矩阵→4，两轴可锁→3，备选数≥3→2，其余→3。保留判断顺序。
- M5：来源数≥6→5，≥5→4，≥3→3，≥1→2，0→1。
- M6：类型基准均值+一致性因子（high+1/mid0/low−1）+时效+平台独立性修正，Python round后截到1–5。日期中位月龄≤36不扣、≤48扣0.25、其余扣0.5；平台独立比例≥0.8不扣、≥0.6扣0.25、其余扣0.5。
- M7：own+churn修正（stable0/moderate−0.25/fast−0.5），按原Python round后截到1–5。部分小数修正可能因舍入不改变分数，不为获得差异而调整舍入。
- M8：`c=rounds+0.5*fetch+4*fetch_fail`；c≤1.5→5，≤2.5→4，≤4→3，≤6→2，其余→1。分越高表示成本越低。
- M9：exact5/mostly4/range3/none2。
- M10：copyrun5/params4/partial3/skeleton2。

M8的0.5将一次获取按半个搜索单位计；4是获取失败额外触发识别、换入口/词、重新获取、复判等返工的设计惩罚，不是每次都真实执行四步的测量结论。失败获取已计入fetch，因此每次失败获取在获取相关项中共贡献4.5。保留既定系数，不称为实测耗时比。

```text
nm(v) = v/5；“受阻”渠道按0
OFF = nm(M1) × nm(M2) × nm(M3)
SEC = nm(M5) × nm(M6)
OWN = nm(M7)
K = 1 − (1−OFF)(1−SEC)(1−OWN)
M11 = K × (0.7+0.3×nm(M4)) × (0.9+0.1×nm(M8))
```

正常1–5输入下版本乘子为0.76–1，成本乘子为0.92–1；原“±30%/±10%”文字不准确。M9/M10不进入M11。M11≥.80高、≥.63中高、≥.45中、≥.24低，其余很低。保留完整精度计算及中间量，展示分四舍五入到3位；分析使用overall_exact。

这些渠道量为规则构造的支撑指标，noisy-OR为聚合假设，不能直接当成经过校准的成功概率或证明实际渠道独立。

## 缺失与零来源的处理

1. `null`表示未能确定观测，在独立字段状态中解释unknown/not_exposed/not_checked等原因；不转换为0或最低分。
2. 正式输入每个所需字段必须有evidence_refs。缺引用保留unverified；脚本检查引用格式，引用文件及内容由日志检查和复核确认，不能凭一个字符串证明证据真实。
3. 确认sources=[]：M5=1，M6="无来源"，归一M6=0，因而SEC=0。区分“未检查来源”或“没有日志”这种sources=null情况。这是新增的零来源边界定义，修复原除零错误，没有伪造M6最低分。
4. M11所需M1–M8任一仍是null，不生成M11。即使某渠道已知受阻，当前实现保守保留缺失状态，不替其他未知指标填值。M9/M10缺失不会阻止M11计算。
5. core_fetch未知但body_status表明正文已取得时，M3可单独评分；core_fetch未知且body_status=not_retrieved时，M3为受阻。不能用这个旁路填M2。
6. 不同规则版本的输入不能在一次计分中混用；旧结果不自动迁移。
